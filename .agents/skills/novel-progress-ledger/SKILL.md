# novel-progress-ledger｜全书创作进度台账（纯文本工作流）

## 1. 唯一数据源与文件职责

本项目的记录全部采用 UTF-8 Markdown，直接在 GitHub 或 Codex 中编辑。**不生成、不维护、不要求运行 Python 脚本；不再维护活动 CSV、JSON 或 XLSX 台账。**

| 文件 | 唯一职责 | 维护方式 |
| --- | --- | --- |
| `05-写作计划/创作阶段进度.md` | 全书18卷、每篇的卷纲/章纲/简写/正文写作与审核状态、最新结论 | 直接更新对应行和卷级统计 |
| `05-写作计划/阶段审核记录.md` | 每次真实审核的追加式历史事件、受审版本、报告、结论、分数 | 只追加，不覆盖旧事件 |
| `05-写作计划/创作阶段状态确认.md` | 作者明确确认的历史写作/审核流程状态 | 只按作者确认更新，不能代替正式报告 |
| `05-写作计划/正文审核进行中.md` | 已开始但尚未形成正式报告的审核工作 | 开始时登记，完成后移除 |
| `08-审稿/章节最终审核总表.md` | 正文终审唯一权威登记，一篇一条当前结果 | 复审时更新原篇目，不重复造行 |
| `08-审稿/对应章节正式审查报告.md` | 每轮完整审查证据、问题、评分、修订与验收 | 每轮独立归档，不覆盖历史报告 |

上述文件之间职责分离。进度表是状态索引；阶段审核历史是事件证据；作者确认是流程状态；正文终审总表是正文质量结果。任何一个都不能代替其他记录。

## 2. 四阶段状态口径

| 阶段 | 已写的可核依据 | 已审核的可核依据 |
| --- | --- | --- |
| 卷纲 | 当前有效卷纲文件确有目标卷内容 | 对应当前卷纲版本的正式审核报告和事件 |
| 章纲 | 当前有效章纲中确有目标篇目 | 对应篇目/整卷覆盖范围的正式审核报告和事件 |
| 章节简写 | 对应编号章或独立插章的实际简写文件存在 | 逐篇剧情审核报告、明确结论及受审版本 |
| 正式正文 | 对应编号章或独立插章的正文 MD 存在 | 正式正文审查报告及阶段审核事件 |

- 写完不等于审完；已审不等于审核通过；作者确认不等于质量审核通过。
- 状态必须分别表达“未写/已写”“未审/已审”“通过/不通过/待复核/待核实”，不能把它们压成一个完成标记。
- 相邻上游一致性门禁依 `stage-consistency-gate.md` 执行。确证实质偏离登记“不通过”；材料缺失、版本不明或无法核实时登记“待核实”；不得因高分自动放行。
- 阶段三章节简写每篇当前版本必须达到正式规则要求的80分，且一致性、P级、版本和报告门禁均通过，才可登记通过。
- 正文文学质量、AI味专项、上游一致性、TXT同步、合订本同步、工程交付分别记录，不得相互替代。

## 3. 写作或审核完成后的直接更新事务

每次新建、修改、删除、拆章、换纲、完成审核或改变阶段状态后，在同一次交付中执行以下人工文本更新：

1. **核对真实成果物**：确认目标卷、篇目、当前正文/章纲/简写路径和当前版本；不从旧索引或文件名猜测。
2. **正式审核事件**：只有真实完成审核并形成仓库内正式报告后，才在 `阶段审核记录.md` 对应卷下追加一行。记录卷、篇目、阶段、结论、分数（适用时）、审核时间、受审源稿路径、SHA256（可获得时）、报告路径和简要证据。
3. **正文终审总表**：若为正式正文审查，更新 `章节最终审核总表.md` 中该篇目的当前索引行和详细字段。一个篇目只保留一条当前结果；旧轮次报告和阶段审核历史不删除。
4. **进度表**：更新 `创作阶段进度.md` 对应篇目的四阶段状态、最新审核结论、分数、报告路径；若篇目数量、章位或卷纲状态变化，同步更新卷级统计。
5. **作者确认**：只有作者明确确认的历史流程状态才写入 `创作阶段状态确认.md`，保留确认日期、范围和依据。不得把确认状态写成正式审核事件。
6. **进行中记录**：初审确实开始但未形成报告时，更新 `正文审核进行中.md`；正式报告形成后移除对应条目，并追加正式事件。
7. **复核**：人工检查篇目唯一、报告路径有效、分数与报告一致、SHA256没有复制错位、各类状态没有混淆。无法核实的字段明确写“待核实”，不得猜测。

禁止运行进度生成器、导出脚本或用临时程序批量覆盖人工台账。禁止重新创建 CSV/XLSX/JSON 镜像。不能完成某项人工核对时，明确写出未核实项，不得声称自动校验 PASS。

## 4. 正文与 TXT 阅读副本同步

- Markdown 正文是唯一权威源。TXT 和卷合订本只是阅读副本，不得反向覆盖正文。
- 每次正文新增或修订后，直接更新对应单章 TXT，并在分卷合订本中唯一替换该章节区块。
- TXT 必须遵守项目格式：UTF-8纯文本、无 Markdown 标记、不删改或润色正文；章节标题是否写入、文件名、段首缩进、段落换行和场景空行依项目规则。
- 人工逐项核对：章节标题正确且不重复；正文段落数量和顺序对应；内容无遗漏、重复、缩写或擅自润色；合订本中目标章节只出现一次；前后章节顺序不变；其他章节区块未被误改。
- 只完成写入但没有逐项对照时，状态记“已同步，待核验”；完成逐字/段落对照后记“文本核对通过”。不再存在“官方 Python 导出 --check”门禁。

## 5. 进度表的维护规则

- `创作阶段进度.md` 是手工维护的唯一权威总览，保留18卷总览和逐篇明细。
- 每次审核只更新实际覆盖的篇目；整卷审核必须逐篇有报告证据，禁止将抽样结果批量填入全卷。
- 作者历史确认只保留流程状态，不能补造分数、报告、AI味结论、源稿指纹或工程验收。
- 旧卷合并后的历史审核事件继续保留，但标记失效的旧卷记录不得用于现行新卷写作准入。
- 未分章卷只记录卷级状态和章数未定，不虚构章节。
- `07-创作记忆/作者人工复核进度.md` 是作者专属人工复核表，除非作者本次明确要求，否则禁止自动修改。

## 6. 正文终审总表字段

终审总表每篇保留：作品、卷、篇目标识、标题、正文MD路径、基线版本/commit、报告路径、日期、初审总分、最终总分、分数变化、七维最终原始分、AI味专项结论与37项问题计数、初审确证问题数、确认修复数、最终遗留问题数、P0/P1数、修订/回滚次数、文学质量、上游一致性、工程交付、单章TXT、合订本、反方方式、正文SHA256、钩子诊断（独立诊断，不并入正式总分）及备注。

正文七维权重和总分公式只服从 `review-core.md`。AI味专项绝不数值化。总体验收只汇总适用门禁，不创造新评分标准。
