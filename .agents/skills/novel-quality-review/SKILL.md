# 小说质量与逻辑深度审查（Novel Quality Review）

## 适用边界

- 适用单章、多章、整卷及“旧版→新版”复审；允许只做特定维度，但**输出栏目顺序不变**，未评项标注「本轮未评」。
- 先读项目的 `AGENTS.md`、`08-审稿/章节审稿与质检标准.md`；评分细则见 [references/scoring.md](references/scoring.md)，检查表见 [references/checklist.md](references/checklist.md)，**最终报告一律按** [references/report-template.md](references/report-template.md)。
- 本仓库《崖边戍卒》默认范围仅前四卷；第一至四卷单章正文 **4000—5000 汉字**为现行硬约束。第五卷以后若未要求，不参与评分，不以废弃草案作为现行定稿。
- 默认**只读正文与设定并生成报告**；不重写正文、不改世界观与人物档案、不覆盖旧审稿报告。仅用户明确要求修改时才修改，并先按优先级最小改动。

## 输入解析与审稿深度

接收章节范围、文档路径、稿件版本、是否要求跨章对照、是否要求复审。没有指定范围时优先当前进度所指**已完成章节**，不要把未完成稿当已发布章节。单章至少读取前一章结尾与后一章已存在的相关段落；多章逐章完整阅读后再横向对账。

三个深度共用一份报告格式：

- `quick`：章节全文 + 最近相邻章节/摘要 + 必要的设定；允许对未取得来源标「待核实」。
- `standard`（默认）：每章全文、任务卡、人物、时空、武器规则、上下章、动态账本与伏笔。
- `deep`：以上全部 + 跨章事件与资源台账、敌我态势、读者/角色/作者知识差异、旧评估问题复发检查。

读写分离；信息缺失时提出待核实项，**不能用记忆或旧报告冒充重新检查正文**。

## 工作流：必须按顺序

### 1. 构造证据清单（渐进加载，不全库扫读）

1. 明确：章节编号、文件 SHA 或版本/检查日期、正文路径、审查范围。
2. 读取 `06-正文/...` 的**完整正文**，保持原始行号；跨章建立「章节→事件→参与者→时间→地理位置→资源/伤情→信息出处」表。
3. 读取权威来源：`01-世界观/` 与本章事件相关的专题；`02-人物/` 本章出场人物档案；`03-剧情/` 当前卷、伏笔；`04-文风/文风总规范.md` 与 `04-文风/禁用表达与常见问题.md`；`05-写作计划/章节任务卡/`；`07-创作记忆/` 状态、时间线、伏笔。
4. **权威冲突处理**：先区分「正文自相矛盾」「正文与有效设定不一致」「设定文件彼此冲突」「角色有意说谎/误判」「作者故意留悬念」；前两类才直接归为正文逻辑错误。文档互相冲突时列成「设定待裁决」，不能擅自把一个版本说成事实。
5. **信息分层**：角色实际知道、读者已经知道、作者秘密，各自独立；审稿可以核对作者秘密，但**任何示例改写不得向正文读者提前剧透**。

### 2. 做机械性事实预检（不可代替通读）

- 优先运行 `python3 .agents/skills/novel-quality-review/scripts/scan_chapter.py 06-正文/第一卷/第001章.md`，按需要加 `--json`；失败就手动统计并标明方法。
- 固定报告两个数字：**正文汉字数（不含标题、空白、Markdown 标记）**、**正文非空白字符数（含正文标点）**，不混称「字数」。前四卷按**正文汉字数**判 4000—5000 红线；出现其他计算口径冲突要说明，不替旧报告猜测。
- 关键词命中仅为「待检查的文本现象」，不是 AI 作者识别，更不是直接的质量扣分或一票否决。需要**原文+上下文**才能判定。
- 时间表、距离/速度/地形、天气、射界、装备取得/消耗/弹药兼容、伤情恢复、权限/情报来源单独对账。做不了精确运算的标「估算，需确认」。

### 3. 再做人读审查（先硬逻辑，后语言）

依次做：①叙事实际发生什么（不先相信摘要）；②主因果、角色动机与消息/证据链；③时空物理与战术；④世界观装备/超感上限；⑤人物性格与伤损连续性；⑥伏笔节奏与跨章升级；⑦语言自然度与 AI 式表达；⑧网文阅读体验。

细项见 [references/checklist.md](references/checklist.md)。不得只靠禁用词计数得出「AI味浓」，也不得因句子华丽、冷峻、短句、比喻就认定 AI。允许有意使用的军人口令、专业术语、情绪高潮和类型化表达。

### 4. 提出问题必须绑定证据和替代方案

每条问题以 `L-001`（逻辑）、`A-001`（AI式表达）、`R-001`（节奏/人物/可读性）、`C-001`（配置/字数/设定冲突）等稳定 ID 标识，复审保持 ID。

每条至少给出：

1. **位置**：章节、仓库相对路径、行号范围（能定位时）及 15—80 字原文摘录；跨章问题至少列两处证据。
2. **判定**：`已证实`/`高可信推断`/`待核实`，严重度 `P0/P1/P2/P3`，类型。
3. **理由**：为什么读者会产生矛盾/疑惑，证据如何支持；区分事实、角色猜测和审稿人的外部常识。
4. **最小修改**：优先「删半句、改说法、补代价、补1个动作、交代来源、移动铺垫」；必要时提供**短对照片段**，不为了显得会写而重写整章。
5. **波及范围与验收**：本章、相邻章、任务卡、动态账本、伏笔记录需要同步核对什么；改完怎样复查。

不要笼统说「逻辑不合理」「很 AI」「节奏拖沓」；不能把疑点写成已证实。对每一条已证实的 P0/P1，给可执行修改指令，不能只有评价。

### 5. 统一计分与发布判定

- 按 [references/scoring.md](references/scoring.md) 七个维度**分别以 0—10 分打分**，乘权重合计 **100 分**；另报：`AI式痕迹显著度 0—5`（越高越明显），**不是“AI生成概率”**；`证据覆盖率`（已全文读完章节数/本次应读章节数，附外部依据缺失项）。
- 如果本轮未完成必要阅读：标「待核实，暂不出发布判定」，不得给出假装精确的合计分；可以提供已审范围的暂定分，但必须明确缺项。
- 对已完整审稿的**前四卷**：实际正文字数越界、明确的硬性设定冲突、未解决的 P0/P1 → **BLOCKED**；否则 **PASS**（P2/P3 附后续建议）。总分高不覆盖硬性拦截；对不在前四卷的章节不自动套用字数红线。
- 必须同时保留**本轮优点/建议保留的细节**，避免「去 AI 味」把人物毛边与场景触感也删没。

### 6. 统一输出、复审与留档

无论章节数多少，最终严格按照 [references/report-template.md](references/report-template.md) **原顺序、同表头、同问题字段**完整输出；多章另附逐章表、跨章冲突表，**不替代**主报告。问题超过 20 条时正文展示最关键问题并给全部问题清单文件，不可悄悄省略 P0/P1。

- 默认在对话中给报告；如被要求落盘，将新报告放 `08-审稿/`：
  - 单章：`第XXX章-深度质检报告.md`；
  - 多章：`第XXX-YYY章-综合质检报告.md`；
  - 复审：上述名称加 `-复审YYYYMMDD.md`，不覆盖已有旧版。
- 复审先读上一版报告，同一个问题沿用 ID 并标 `已修复/部分修复/未修复/误报/待复核`；重算分数、复核修改引入的新问题，列出前后差值，不能只说「明显改善」。
- 若用户明确要求改正文，**先审查再定向修改再复审**。默认不碰作者关键命运与正史设定；后续章节尚未设计时，不倒推其必须发生的事件。
