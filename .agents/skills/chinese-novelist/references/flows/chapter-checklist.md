# 逐章创作流程（所有写作模式共用）

> **v8 新增详写门禁**：执行阶段 A 与本章概要/约500字简写用户审核后，改走 [webnovel-writer v8 正文适配协议](webnovel-writer-v8-adapter.md)：十段材料→单章草稿→八维审读→定向改稿→候选事实核对。必须继续本清单的四关去AI味、独立反方、设定时间轴和 MD/TXT 交付；两套质检交叉验证而不重复扣分，插章不限制字数。


> 本文件是逐章创作流程的**单一事实源**。串行模式、子Agent并行模式、Agent Teams 模式均执行本清单，各模式仅"如何认领下一章"不同（见 [phase3-writing.md](phase3-writing.md)）。
>
> `{skillBaseDir}` 为 skill 安装根目录占位符，由主 Agent 在派生子 Agent 时替换为实际绝对路径。

## 跨阵营视角插章检查（每章规划前顺手核对，不强制插章）

- 读本章相邻事件，问主角团队是否遗漏了影响后续因果的阵营决策、后勤困境、基层抵抗或平民选择；仅在形成**新行动＋新后果**时规划有限第三人称插章，不能复述战斗、替作者讲背景、预支秘密。
- 标题明确标出【锐科视角】／【弘毅领视角】／【白汀视角】等实际阵营；注明插入章号、真实时序、视角人所知事实、不得提前揭露之事和所付代价。编号正文和跨卷直接接战不可被割断。
- 势力不得被简化为单纯坏人，也不能因生存困境免于对越界、隐瞒和伤民行为负责。锐科可呈现污染区生态穹顶能耗及净化系统危机，但工程、军方、管理层的信息与目标不应默认相同。
- 插章概要和约500字简写**单独提交用户审核**；批准后方写全文。插章不限字数且不参与常规篇幅评分与阻断，仍执行连续性、人物建档、去AI味和双格式交付。

## 阶段 A：写前分析

1. **读取 `02-写作计划.json`** — 确认本章状态，将其 `status` 置为 `"in_progress"`，检测 `architectureMode`（`deep` 或 `standard`）。

### A1. 资料加载与上下文准备（按架构模式分支）

- **若为深度模式（`architectureMode: "deep"` 或存在 `AGENTS.md`）**：严格执行 **JIT 渐进式按需读取协议**（严禁通读全工程所有文档）：
  1. **读取全局中枢与进度**：读取 `AGENTS.md` 与 `07-创作记忆/当前写作进度.md`
  2. **读取动态生理与情报状态**：读取 `07-创作记忆/人物实时状态.md`，提取本章出场角色的实时伤病、位置、持有物资与「已知情报边界」（严防全知剧透）
  3. **读取本章任务卡**：读取 `05-写作计划/章节任务卡/第{XX}章-任务卡.md`（或当前分卷规划中对应小节），提取核心冲突、意外转折、结尾钩子、出场人物
  4. **按需精读人物主档**：仅针对本章出场的角色，读取 `02-人物/` 对应主档（优先检索 `02-人物/主角/`、`02-人物/配角/`、`02-人物/辅助角色/`），重点提炼其**核心行为逻辑**（牺牲底线、抗命条件、失控诱因）与**禁止偏离清单**
  5. **按需读取世界观专题**：若本章涉及特定科技、地理或异象，仅针对性读取对应的单个 `01-世界观/` 专题文档
- **若为标准模式（`architectureMode: "standard"`）**：
  1. 读取 `01-大纲.md` 提取章节规划信息与出场人物
  2. 核对 `01-大纲.md` 设定与事实词典
  3. 读取 `00-人物档案.md` 提取出场角色设定

### A1.2. 战斗／多人协同章节专项加载（深度模式按需触发）

- 若本章涉及交战、巡边侦察、救援、护送、撤民、断后、战场医疗、无人机协同、友邻部队或战后复盘，则读取 `01-世界观/小队作战协同与战斗描写规范.md` 的对应部分，并与 `01-世界观/战力与规则.md`、`01-世界观/武器装备与技术.md`、相关角色小传交叉核对。
- **重要战斗强制补场景卡**：按该规范第十节填写／核实本章任务卡中的“战斗／协同场景卡”，重点是参与者、任务目标、信息边界、支援、限制、结果与后续账本；未锁定数据写“待确认”，不能臆定。
- **动态编组与在场人数核验**：先读取 `07-创作记忆/队伍编组状态总账.md` 的最新**已发生**记录，结合人物实时状态核实当章状态；五人仅为前期某阶段原核心人数，绝非全书固定编制。逐章分别统计**正式成员／现场实到／可执行任务者／独立友邻及保障人员**，按人物加入、调离、伤停、死亡、分组核对实时状态；前四卷原核心结成与阵亡节点保持不变。新增人员须有来历、档案、胜任能力和指挥关系；临时友军不自动归编；人数不足允许任务缩水，人数增多须处理任务分工和信息协调。纯日常章节不强制加载本专题。

**专项适用于非编号插章**：同样盘点主视角人物、具稳定称谓的重复登场者、关键推进者（即使匿名），必须先建小传，记录初始势力、出场章号及信息权限；不因插章不限字数而豁免人物门禁。

### A1.5. 写前出场人员盘点与小传完备性核查（硬性前置拦截：无小传非一次性角色严禁动笔）

> ⚠️ **核心铁律**：**主角和配角都要有人物小传，理论上只要多次出现的人物都要设立小传！**
> 💡 **小传定位（冰山原则与合规基准）**：**小传没必要所有的情节都在正文中提及，只是为性格和人物建立一个基础而已，后续合规性教研的时候可以当做输入。**正文中严禁生搬硬套做简历式全盘倒灌，小传重在确立底层性格基石，并在后续审读质检中作为合规性输入源。严禁“无档人物”在正文中随意发表台词、推动关键转折或无序出场。在动笔撰写正文之前，必须先过此关。

1. **第一步：盘点本章全部参演人员**
   - 提取本章任务卡（`05-写作计划/章节任务卡/第{XX}章-任务卡.md`）或大纲章节规划中记录的「出场人物」列表。
   - 梳理本章计划展开的核心事件与互动，盘点所有即将登场的人物（主角、核心队友、对手敌特、接头人、常驻或功能性 NPC）。
2. **第二步：核对小传完备性**
   - **深度模式**：核对 `02-人物/`（递归加载 `主角/`、`配角/{势力}/`、`辅助角色/{势力}/` 子目录以及根目录）中是否已有对应角色的独立小传文件。
   - **标准模式**：核对 `00-人物档案.md` 中是否已有对应角色记录。
   - 梳理出其中“尚未拥有小传”的新角色名单。
3. **第三步：判定是否需要补充小传（多次出现与关键功能原则）**
   - **必须建档（生成独立小传）的标准**：
     * **主角与配角**：全员必立小传；
     * **多次出现/后续复现角色**：理论上只要在书中多次出现、或未来章节/后续分卷还会再次登场（哪怕只是周期性露面）；
     * **关键情节推动者**：在本章承担了重大剧情推进、提供了关键线索/证物/武器、引发重大危机或决策转折的角色；
     * **有具体姓名与深度交互者**：拥有具体名字、具象性格特质、独特战力或专业技能，与主角/核心团队产生实质性言行或肢体冲突；
     * **特定阵营常驻功能角色**：如防区军医、随军老工匠、特定哨所长官、黑市掮客、敌方侦察小队长等。
   - **免建小传的唯一豁免（纯一次性龙套）**：
     * 仅限纯背景过客、无名背景板，且全书绝无二次登场可能的路人（如“无名小二端上一碗水即退下”、“城门守卫查验路引后挥手放行”等）。
4. **第四步：即时补写小传与三级归档（动笔前必须执行完毕）**
   - 若发现本章登场的主角、配角或多次出现角色缺少小传，**严禁跳过！必须在动笔撰写正文前，先行创建补充该角色的小传文档**：
     * **主角小传**：存入 `02-人物/主角/[角色名].md`（使用[十维深度主档模板](../guides/deep-character-template.md)）；
     * **配角小传**：存入 `02-人物/配角/{初始所属势力}/[角色名].md`（核心副手、主要队友、关键反派）；
     * **辅助角色小传**：存入 `02-人物/辅助角色/{初始所属势力}/第XXX章-[角色名].md` 或 `02-人物/辅助角色/{初始所属势力}/第一卷插章NNN-[角色名].md`（**以首次登场章节命名**，使用[辅助角色精悍小传模板](../guides/deep-character-template.md)）；
     * 同步在 `02-人物/人物总表.md` 登记（区分主角/配角/辅助角色及首次正式登场时的初始势力），并在 `07-创作记忆/人物实时状态.md` 建立初始行；
     * 运行命令同步只读速查：
       ```bash
       python {skillBaseDir}/scripts/sync_novel_memory.py <项目目录> --compile-views
       ```
   - **标准模式**：在 `00-人物档案.md` 的 `## 三、辅助角色（按章节归类） -> ### 第{XX}章` 下补充该角色小传卡片。
5. **第五步：按需加载新角色禁令**：将补写好的新角色小传中的「行为逻辑」与「禁止偏离清单」纳入写中关注范围，并作为后续合规性教研质检的基准输入。

### A2. 语态与衔接落点（双源动态加权文风锚定）

2. **读取双源文风动态权重与指示盘** — 
   - 从 `03-文风基准.md`（或深度模式 `04-文风/文风DNA蒸馏档案.md`）读取【双源文风动态权重指示牌】。
   - **核心铁律**：**文风不仅参考提供的外部文本，更深度参考小说的正文部分；而且小说正文越多，参考自身正文的权重越重！**
   - 当前权重参考（根据已定稿章节 $N$）：
     - $N=0$（第 1 章）：外部参考 100% : 本书正文 0%
     - $N=1$（第 2 章）：外部参考 85% : 本书正文 15%
     - $N=2$（第 3 章）：外部参考 75% : 本书正文 25%
     - $N=4$（第 5 章）：外部参考 55% : 本书正文 45%
     - $N=5\sim 9$（第 6~10 章）：外部参考 45%~20% : 本书正文 55%~80%（内生语调超越外部）
     - $N \ge 10$（中长篇）：外部参考 15%~10% : 本书正文 85%~90%（自身高水准正文成为绝对主导）

3. **双源语态与正文切片加载（注意力头部定桩）** —
   - **加载源 A【外部参考基准（权重 $W_{\text{ext}}$）】**：读取 `04-文风/文风DNA蒸馏档案.md` 或 `03-文风基准.md` 中的【反模式禁令】（假对比、段尾虚浮升华、全员哲学家等红线）与【心智模型/句长底线】。
   - **加载源 B【小说自身正文（权重 $W_{\text{int}}$，正文越多权重越重）】**：
     - **长效黄金样本库**：读取 `03-文风基准.md` 或 `04-文风/原创文风样例.md` 的「本书自生正文黄金沉淀库」（萃取自此前章节的精彩动作白描、地道人物市井台词）；
     - **近邻滚动语态**：读取上一章文件名取自 `02-写作计划.json` 中上一章的 `filePath` 字段，读取其最后 800-1200 字（第 1 章跳过），把握衔接语态、人物情绪落点与语言惯性。
   - 确保动笔前最后装入注意力头部的是**按照当前动态权重配比混合后的正文语态**（正文越多，越以本书定稿章节人物的实际声线与节奏为最高准绳）。

> ⚠️ **动笔前最后读到的必须是正文语态文字（自身高水准段落 + 上一章切片 + 外部黄金段落），严禁让大纲表格和摘要成为动笔前的最后上下文！**

## 每章三步写作（强制流程）

后续每章统一按 **概要设定 → 简写 → 详写** 执行，已有大纲、任务卡也不得跳过。

1. **概要设定**：完成写前核验，先明确本章时地、视角、人物、承接、核心事件与因果、关系推进、结尾及连续性限制，遵循已有权威设定。
2. **简写（约500字）**：根据概要设定写出连贯的精简叙事，呈现起因、行动、变化与结果。提交概要设定和简写后，必须停下等待用户审核；只有用户明确通过该章简写后，才能详写。用户要求调整时优先局部、小幅修改，保留未被要求改变的情节、结构和动机；修改后再次提交审核。用户明确要求大改时才扩大范围。
3. **详写（编号常规章4500—5000字；外部第三视角插章不限字数）**：以获批简写为依据展开动作、对话、感官与因果细节，不擅改关键事件、人物选择和结局。完成后执行去AI味四关、既有质检、事实回写与MD/TXT交付。仅编号常规章须达到4500—5000字，不得用旧版3000或4000字下限替代；仅其机检支持时使用 --min-words 4500，并人工复核上限。插章不得套用该字数门禁。

概要设定、简写及审核状态存入任务卡或规划草稿，注明“待审核／已通过”。未获批草稿不作为正式正文或已发生事实，不标记章节完成，不适用正文篇幅质检与TXT导出。中断恢复先查审核状态；沉默、超时及上一章通过均不等于本章通过。每章分别审核。此规则适用于串行、批量及多Agent模式，优先于旧流程中的“无需确认／全程不中断”；用户审核不能由Agent代替。

## 阶段 B：详写（本章简写获用户明确通过后）

4. **创建章节文件** — 文件名格式：`第{XX}章-{章节标题}.md`（或 `06-正文/第X卷/第{XX}章-{章节标题}.md`，路径以 `02-写作计划.json` 中的 `filePath` 为准），使用 [chapter-template.md](../guides/chapter-template.md) 模板
5. **撰写章首引子** — 按大纲或任务卡中的章首引子类型，参考 [hook-techniques.md](../guides/hook-techniques.md)「章首引子七式」，创作 50-150 字的引子文字
6. **撰写正文** — **仅编号常规章详写须达到4500—5000字；非编号第三视角插章不限字数**，硬性要求：
   - 正文开头：第一段必须使用 [chapter-guide.md](../guides/chapter-guide.md) 十种开头技巧之一，建立即时冲突
   - 张力节奏：全章至少 2 个张力波峰，连续 500 字以上无冲突时必须引入新张力（参考 [hook-techniques.md](../guides/hook-techniques.md) 悬念强度等级）
   - 对话要求：每章至少 30% 对话内容，每段对话必须有潜台词或推进情节目的（参考 [dialogue-writing.md](../guides/dialogue-writing.md)）
   - 意外转折：每章至少 1 个读者预期之外的事件或信息（参考 [chapter-guide.md](../guides/chapter-guide.md)「打破读者预期」）
   - **动态约束遵循**：角色的机动与行动必须严格符合 `人物实时状态.md` 中的身体健康、伤病、体能与装备余量，绝不无故超人化
   - **情报边界遵循**：角色言行严格受限于已知信息，严禁以全知心理活动抢先揭秘未到期伏笔
   - **行为逻辑与负面禁令**：严格符合人物小传中的行为底层逻辑，坚决不触发「禁止偏离清单」中的任何条款。遵守冰山原则：小传没必要所有的情节都在正文中提及，只是为性格和人物建立坚实地基，正文通过具体行动与抉择体现性格，切忌简历式交代生平。
   - **战斗协同落地（仅相关章节）**：按 `01-世界观/小队作战协同与战斗描写规范.md` 展示职责与互斥兼岗、已知情报、指挥取舍、资源限制、战后余波；绝不把参考资料变成正文术语说明书。
   - 内容不足？使用 [content-expansion.md](../guides/content-expansion.md) 扩充技巧
7. **设置结尾钩子** — 按大纲或任务卡中的悬念钩子设计 → [hook-techniques.md](../guides/hook-techniques.md)「悬念钩子十三式」

## 阶段 C：撰写后优化与四维硬质检

### C1. 去 AI 味四关（Humanizer-zh / speak-human-tw / shuorenhua / lieflat 全部过一遍，硬性前置）

> **硬规则：每章写完，四关必须全部过一遍，任一关 BLOCKED 一律不得进入 C2 与阶段 D。**
> 四关总览与本地化理由见 [ai-tone/README.md](../ai-tone/README.md)；单页执行卡见 [ai-tone/chapter-gate-runbook.md](../ai-tone/chapter-gate-runbook.md)。

8. **张力与节奏检查** — 全章节奏是否有波峰波谷、对话是否有潜台词、是否有意外转折。

9. **机检：四关机械合检并落盘报告（先跑，再动手）**
   ```bash
   python {skillBaseDir}/scripts/scan_ai_tone.py <章节文件路径> --project-dir <项目目录> --auto-report --json
   ```
   - 退出码 `0` = 无阻断（可能带 WARN）；`1` = BLOCKED；`2` = 文件错误。
   - 本流程详写按4500—5000字取 `--min-words 4500`；不得用旧版3000或4000字下限替代。
   - 报告自动写入 `08-审稿/第{XX}章-去AI味四关报告.md`，含四关汇总、阻断项、待裁量项、机械指标。
   - **阻断项必须先改完，再进人工四关**（否则会在将被删的句子上白费功夫）。

10. **人工四关（依次过，不许跳关、不许合并）**
    - **G1 Humanizer-zh（抬高与套式）** → [gate-1-humanizer-zh.md](../ai-tone/gate-1-humanizer-zh.md)
      清假对比、意义拔高、宣传语、借权威、句尾抒情尾巴、AI 高频词；只改命中句，不补写更漂亮的句子。
    - **G2 speak-human-tw（空转与腔调）** → [gate-2-speak-human-tw.md](../ai-tone/gate-2-speak-human-tw.md)
      清公式化开场、立场真空、三段式、假推论、空话收束；罐头反应镜头逐处判断（删了会漏信息才保留），**不许换成同族镜头**。台湾在地化层不引入。
    - **G3 shuorenhua（翻译腔与公文腔）** → [gate-3-shuorenhua.md](../ai-tone/gate-3-shuorenhua.md)
      「对……进行了……」等名词化动作还原成可拍动作；翻译腔只处理白名单五类；核对情态守恒与情报边界（不得把「可能」写成「一定」）。
    - **G4 lieflat（结构与节奏套式）** → [gate-4-lieflat-less-ai-tone.md](../ai-tone/gate-4-lieflat-less-ai-tone.md)
      翻案腔分级（抽象命题改、事实辨识保留）、顿号罗列、相邻句同构、破折号密度、冒号提示语、序数小标题、段首零主语；**白名单外一个字不改**。

11. **判定与留痕** — 改完重跑机检，直到 `block_count == 0`；每条 WARN 在报告中写「保留（理由）」或「已改（改成什么）」，并在报告末尾追加【人工四关执行记录】（模板见 runbook 第四节）。空白通过视为未执行。
    - 判定 `BLOCKED`：回阶段 B 定向重写，**严禁回写账本、严禁归档**。
    - 判定 `PASS` / `PASS_WITH_WARNINGS`：进入 C2。

    > 三个脚本的分工：`scan_ai_tone.py` 管 AI 味（本节）；`scan_chapter.py` 管字数与套式快扫；`verify_chapter_consistency.py` 管时间轴/因果/人设（C2）。三个都 PASS 才允许阶段 D。

#### C1.4 对抗式 AI 味审稿子智能体（每章强制）

- [ ] 依 [对抗式 AI 味审稿协议](../ai-tone/adversarial-ai-review.md)，由主 Agent **真实派生** `ai-style-red-team-reviewer` 独立反方审稿（支持 Task / spawn agent 等能力时必须调用），不向它提供主审 PASS、分数及辩解；子智能体只攻击与举证，不修改正文。
- [ ] 反方覆盖 G1—G4、12.7 毫米等装备重复说明、同构战斗/救援、动作和环境套式、副词/形容词堆叠、场景叙事必要性；每项列真实行号、原文、复现证据、反证及最小修法。主审逐项裁定 `成立/部分成立/被推翻/待核实`，不得为凑 AI 味凭词频造问题。
- [ ] 四关审稿记录和质检报告增加「独立反方审稿」执行情况及攻击—裁决表；修改后重跑对抗复检。**无实际子智能体创建能力时标记「未实际派生／降级反方审查」而不造假**。未留痕不得声称完成独立对抗审稿。

#### C1.5 本书自有铁律（优先级高于四关，逐条落地）

- **【规约 1：绝对保事实（说人话原则）】**：改写润色严禁丢掉任何既定伏笔、伤病状态、时间数字、装备名称与因果关系，绝不为了语言平滑而篡改剧情事实。
- **【规约 2：彻底清除假对比与拔高（Humanizer-zh 原则）】**：
  - 坚决删除“不仅……更是……”、“看似……实则……”、“表面上……暗地里……”。
  - 坚决删除每段/每章结尾的虚浮哲学升华（如“这不仅是一次冲锋，更是对命运的反抗”一律抹除）。
  - 例外：侦察辨识、验尸推断、装备判别中的“不是A而是B”属本书核心叙事动作，保留。
- **【规约 3：消灭翻译腔与公文动词（说人话原则）】**：
  - 将“对XX进行了攻击”改回“挥刀直劈”；将“给予了沉重打击”改回“一拳砸碎对方下颌”。
  - 减少“作为……”、“具有……”等僵硬公文句式。
- **【规约 4：破除成语堆叠与破折号滥用（Humanizer-zh 原则）】**：
  - 严禁连续 3 个以上四字成语轰炸，打破僵硬律动，增加长短句交错的呼吸感。
  - 精简“——”破折号，非对话强行打断场景严禁无节制使用（阈值 >1.5 次/千字记 WARN，>3 次/千字记 BLOCK）。
- **【规约 5：生活化与台词毛边感】**：
  - 角色台词必须符合身份背景，带留白与口语停顿，坚决剔除字正腔圆的 AI 播音腔与现代网梗。
- **【规约 6：控台词密度与反全员哲学家（吸收《团长》铁律）】**：
  - 严格控制台词密度，**绝不能让每个人都变成善于讲道理的人**。严禁角色突然发表长篇哲学演讲，大道理烂在肚里，多说市井粗粝大白话与生活琐碎。
- **【规约 7：重人物关系，轻专业术语（吸收《士兵突击》铁律）】**：
  - **重点是人物之间的关系变化，而非军事/专业术语！**严禁把装备写成百科说明书，重点写肢体动作、眼神与生死托付。
- **【规约 8：节奏张弛与无代价光环阻断（吸收《第一序列》铁律）】**：
  - 贯彻“危险与日常的交替（一张一弛）”，高压交火后必须有安全屋修整（包扎、热汤、战利品清点）与阶段性情绪回报。
  - **绝不借鉴无代价的主角光环**，一切战果必须付出肉体伤残、耗材见底或生理反噬等真实代价。

### C2. 四维多维一致性硬拦截质检（Quality Gate，四关 PASS 后方可执行；未通过严禁进入阶段 D）

在 C1 四关判定为 `PASS` / `PASS_WITH_WARNINGS` 之后，执行**四维硬核验**，确保章节逻辑闭环：

1. **维度一：时间轴与多主角生命线/主线事件合规性核验（Timeline & Chronology Gate）**：
   - **世界主线时间节点锚定**：明确章节的世界纪元年份、月份与节气。严禁出现时间倒流或反季节天候描写（如寒冬描写盛夏蝉鸣骄阳似火）。
   - **多主角实岁与生命阶段核算**：主角当前实际年龄 = $\text{当前世界年份} - \text{主角出生年份}$。正文出现的自报年龄与称谓必须与理论实岁严格一致（误差 $\ge 1$ 岁阻断）。主角未出生严禁出场、阵亡后严禁现场行动、后卷角色严禁跨卷提前登场互动、行为能力受人生阶段严格约束。
   - **主线大事件时刻表核验**：对照 `worldEventsTimeline`，严禁将未来尚未发生的重大事件（如全面热战爆发、城邦陷落）在当前章节写成已发生事实（早产剧透阻断）。
   - **时空位移耗时硬约束**：跨地域机动用时必须符合地理尺度与交通工具物理耗时规则，严禁瞬移。
2. **维度二：情节合理性与状态继承（Plot Plausibility & Injury Continuity）**：
   - **生理与伤病继承**：核对 `07-创作记忆/人物实时状态.md`，上章的骨折、内伤、中毒必须在行动中产生阻碍，严禁无铺垫“满血复活”或无代价超常发挥。
   - **因果与装备守恒**：破局手段必须有前置铺垫，消耗的弹药、符箓、物资已从底表扣减，严禁机械降神。
3. **维度三：人物小传合规性教研与负面禁令核验（Bios Compliance & Negative Constraints）**：
   - **小传作为合规性校验输入（Ground Truth Input）**：将出场角色（主角、配角、多次出现角色）的独立小传作为输入源。核查角色抉择、台词口吻、情绪反应是否符合小传设立的性格底色。
   - **冰山原则校验尺度**：**小传没必要所有的情节都在正文中提及，只是为性格和人物建立一个基础而已**。校验核心在于言行不违背人设逻辑，切忌苛求正文全盘复述小传情节。
   - **底层动机遵循**：角色决断必须符合其性格核心与行为底层逻辑。
   - **负面禁令（禁止偏离清单）**：严格核对小传文档中的【禁止偏离清单】，严禁触犯任何一条明确禁止的行为。
   - **已知情报边界（严防全知剧透）**：角色对话与心理活动严格受限于已知信息，严禁以全知视角泄漏未解开的深层伏笔。
4. **维度四：字数硬指标（详写4500—5000字）**：
   - 汉字正文字数必须落在 4500—5000 字区间：不足 4500 字必须使用 [content-expansion.md](../guides/content-expansion.md) 扩充，超过 5000 字必须拆章重写，不得强行塞入单章或注水裁剪。

#### 战斗协同专项人工复核（仅相关章节）

在原四维核验之后，对照 `01-世界观/小队作战协同与战斗描写规范.md` 第2节及第十一节，逐条检查：正式成员数、实到人数、当前可用人数、独立友邻人数是否有区别；增员／减员／伤停／分组与命运阶段是否一致；新人技能和指挥权限是否有来源；以及信息获取／报告时序、伤病、装备和补给消耗、平民及伤员去处、责任与结果因果。对 P1（严重硬冲突）必须定向修正；对 P2（证据不足）补回正文支持；P3 只修不自然的战斗表达。**现有脚本未增加这套专业语义识别能力；必须明确由人工／Agent 执行，不能拿脚本 PASS 代替该专项结论**。在本章质检报告补“战斗协同专项”记录；不改变原四维和八项质检结构。

- **若判定为 `BLOCKED`（存在阻断性问题）**：
  > ⚠️ **严禁进入阶段 D**！必须根据脚本输出的 `issues` 清单定位正文冲突段落，进行针对性重写与修正，并再次运行脚本复检，直至返回 `PASS`（退出码 0）。
