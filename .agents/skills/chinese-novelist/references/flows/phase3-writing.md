# 第三阶段：概要设定、简写与详写

> 详写以本章大纲和简写为依据；**简写当前有效版本正式审核通过**后才允许进入正文，不能只凭写完或曾经审过。v8 备料、起草、审读及事实沉淀仍可按需执行；**质量语义审稿只执行 [统一核心协议](../guides/review-core.md) 的一轮五类检查**，旧 G1–G4、S/F/TR/PAM 专项不逐关叠加。机械扫描、跨章事实与 MD/TXT 工程校验保留独立状态，不得冒称外部工具或子Agent实际已调用。


所有模式遵循 SKILL.md 的“全书大纲→分卷章纲→章节简写→正文”四阶段流程；新写作开始前须按 Skill 第2节和 [写作准入硬门禁](../guides/stage-entry-gate.md) 核对正式审核通过证据（章纲先有卷纲通过、简写先有章纲通过、正文先有简写通过）；缺项、未通过或过期时直接阻断新稿，不能询问带缺项继续；同时遵循核心审核协议；[逐章轻量流程](chapter-checklist.md) 负责写前与写后阶段组织，不作为第二套文学评分。

1. 读取计划、当前进度和任务卡，确认章节及审核状态，按需加载资料。
2. 在章节规划或正文出现**外部势力导致主角未知的关键因果**时，执行 SKILL.md 的“多势力第三方有限视角插章”五问；仅在能提供独立行动、选择与后果时提出插章候选，标清阵营、插入位置和已确认／待审核状态。不能将既有正文章节硬改为插章，插章也须先完成并审核通过其章纲才能写简写，简写正式审核通过才能进入正文；
3. 执行清单阶段A，输出概要设定：时地、视角、人物、承接、核心事件与因果、关系推进、结尾及连续性限制。
4. 按小说项目 `novel.project.json` 的 `brief_target_han` 编写连贯简写，与概要设定一起存入任务卡或规划草稿，待简写**正式审核通过且报告证据有效**后方可进入正文阶段。
5. 用户要求调整时优先小幅、局部修改，保留未被要求变更的情节与结构；修改后再次提交审核。
6. 本章简写**正式审核通过且匹配当前版本**后，才自动执行阶段B：**起草前**按场景列在场人物和各自声口（谁直说、谁谨慎、谁打趣，依据人物小传，不贴固定标签）；**每段初稿写时**优先说清事实/行动，避免把不知道写成免责声明、把旁白写成审批流程；**每句对白先按人物口语写**：明确对话对象和当下目的，用符合身份的词汇、自然断句、插话或省略传递必要信息，避免人人完整汇报“先A再B”、成串列条款或惯性加“不敢保证”；**多人对白写完立即对比**是否同款「不能保证/仍要核实/不替谁说」，真有法律/军令后果则保留。执行 [统一核心协议](../guides/review-core.md) 的AI味37项逐项裁决规则，再按项目配置字数（插章按豁免配置）进入阶段C、D工程核验及事实回写；如项目要求MD/TXT则执行对应交付；不增加第二轮重复审查。
   **防御性句式写时拦截（必做）**：初稿默认直接写眼前事实、动作、选择、人物真正想说的话，极力避免无实际对立对象的“不是……而是……／并非……只是……／这并不意味着……／当然不代表……／看似……实则……”，以及“没有……也没有……只是……”式层叠否定、预设读者反驳、结尾惯性免责或自证合理。每段落笔后先查是否在“先辩解再叙述”；有信息增量则用直陈、可见后果或已有角色言行表达，无增量则删除，不用“实际上／说到底”换壳。写完场景与全章再逐段核查旁白、心理、对白是否重复此类结构。真实误会的纠正、人物在场辩护、必要否定和风险边界均须保留，不凭字面禁词；具体定义和示例见主 [SKILL.md](../../SKILL.md) 的“正文防御性句式抑制”。
   正文起草时优先采用自然常见的语序与搭配：地点、距离等相关信息尽量顺接；连续动作须让读者一遍读清谁在做什么，避免相邻句误接动作主体或修饰对象。复读句子时发现不顺，先在保留事实、语气和节奏的前提下调整；自然倒装、口语和有叙事作用的停顿不必强行改成同一模板。
   起草时先按 [核心协议的叙事逻辑过度显性化与事件报告腔](../guides/review-core.md) 自查：别以逻辑对照替代可见后果，别在关键救援、交涉、冲突里用工作汇报概括人物互动；先判断冗余句能否删除，再判断是否需要展开必要言行，最后才润色。口语化不等于全员粗话、碎句和语气词，职业指令、医疗、合同等必要准确表达要保留。
   起草时同步按 [核心协议的具体描写与对话复核](../guides/review-core.md) 安排装备与环境信息、人物出场和对白提示：优先保留对当前行动、人物关系或情绪有作用的细节，避免无增量的解释与集中罗列；可随行动自然交代，但不强行拆散必要信息。写后在既有审查中核对实际阅读影响及反证，不为追求检测低分牺牲人物声口、专业因果或有效生活细节。
7. 仅在用户请求的章节范围内继续；下一章重新按大纲、简写、正文顺序推进。

中断恢复时按全书大纲→卷纲（审通过）→章纲（审通过）→简写（审通过）→正文核实阶段；上游审核记录缺失、未通过或过期时立即阻断目标新稿，先修复/复审，不能询问“带缺项继续”；只在简写有当前有效的正式通过结论时进入正文。审核前的草稿不回写为已发生事实、不标记章节完成，不执行正文篇幅质检和TXT导出。

默认串行。正文自动写作遵循卷纲审核通过→写章纲并审核通过→写简写并审核通过→写正文的严格顺序及项目事实、连续性和质量门禁。共享文件修改前重读，避免覆盖其他改动。
