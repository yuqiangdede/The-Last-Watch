# 第三阶段：疯狂创作

**重要：全程无需再次向用户确认，必须逐章创作直到完成**

---

## 0. 启动检测与模式读取

开始创作前：
1. 读取 `02-写作计划.json`
2. 读取 `writingMode` 字段，进入对应模式流程
3. 如果存在 `status: "in_progress"` 的章节 → 从该章节继续（中断续写）
4. 如果所有章节 `status: "pending"` → 从第 1 章开始
5. 如果存在 `status: "failed"` 的章节（Phase 4 回退）→ 从第一个 failed 章节开始
6. 如果项目缺少 `03-文风基准.md`（旧版本项目）→ 已有完成章节的，从第 1 章提取最佳段落补生成；一个章节都没有的，按题材生成默认基准
7. **旧项目迁移**：如果 `01-大纲.md` 存在非空「章节摘要」区且 `99-章节摘要.md` 不存在 → 将摘要区内容迁移到 `99-章节摘要.md`，并删除大纲中的「章节摘要」区

---

## 1. 逐章创作流程（所有模式共用）

每一章的完整创作流程统一执行 **[chapter-checklist.md](chapter-checklist.md)**：
- **阶段 A（写前分析与拦截）**：出场人物盘点、**主角/配角与多次登场角色小传完备性核查与即时补齐（小传重在奠定性格基础，并作为后续合规性校验输入；未立小传严禁动笔）**、上一章语态衔接与文风 DNA 锚定；
- **阶段 B（撰写）**：3000-5000字硬指标、人设负面禁令与动态生理状态硬约束（遵守冰山原则，小传情节无需在正文中全盘复述）；
- **阶段 C（润色与质检）**：**去 AI 味四关全过**（G1 Humanizer-zh 抬高与套式 → G2 speak-human-tw 空转与腔调 → G3 shuorenhua 翻译腔与公文腔 → G4 lieflat 结构与节奏套式），以 `scripts/scan_ai_tone.py` 机械合检并落盘 `08-审稿/第{XX}章-去AI味四关报告.md`，任一关 BLOCKED 严禁进入下一阶段；四关 PASS 后再执行以人物小传与时间轴总账为核心输入的四维一致性 Quality Gate 硬拦截（多主角时间生命线、世界主线事件时刻表、情节因果、小传人设禁令、字数红线，支持自动生成规范审稿报告）；
- **阶段 D（事实回写）**：回写人物实时状态、时间线日志与伏笔记录，刷新编译快照。

所有写作模式共用同一份清单，未通过质检严禁进入下一章。

---

## 2. 串行模式（writingMode: "serial"）

**主 Agent 自己逐章创作，全程不中断。**

### 自驱循环

```
WHILE 02-写作计划.json 中存在 status != "completed" 的章节:
    执行 [chapter-checklist.md](chapter-checklist.md) 的完整流程（阶段 A-D）
    ⚠️ 特别注意：阶段 A 动笔前必须盘点本章参与人员。主角和配角都要有人物小传，理论上只要多次出现的人物都要设立小传（按主角/配角/辅助角色+章节归档）。小传重在为性格和人物建立基础，正文无需全盘复述其生平；后续合规性校验（教研质检）将以小传为基准输入。严禁无档裸奔！
    ⚠️ 语态锚定铁律：阶段 A 动笔前必须执行【双源动态加权文风锚定】。文风不仅参考提供的外部文本，更深度参考小说的正文部分；而且小说正文越多，参考自身的权重越重（成熟期自身权重达 80%~90%）。动笔前最后装入上下文的必须是按照当前动态权重混合后的正文语态（本书黄金段落 + 上一章切片 + 外部反模式规约）！
    ⚠️ 去 AI 味四关铁律：阶段 C 必须把 Humanizer-zh / speak-human-tw / shuorenhua / lieflat 四关全部过一遍（见 references/ai-tone/），先跑 scan_ai_tone.py 落盘报告，再逐关人工处理，改完重跑至 block=0。任一关 BLOCKED 严禁回写账本。
    ⚠️ 完成一章后，立即读取 JSON 认领下一章，不要向用户确认，不要停下来
所有章节完成 → 进入第四阶段：自动校验
```

**关键提醒（每章完成后必须遵守）**：
> 本章已完成。立即读取 `02-写作计划.json`，认领下一个 pending 章节，开始下一章创作。不要使用 AskUserQuestion，不要向用户确认，不要停下来。你必须把所有章节创作完成才能与用户报告。

## 3. 子Agent并行模式（writingMode: "subagent-parallel"）

**核心机制**：主 Agent 将章节分成不重叠的批次，每个批次派生一个子 Agent。批次内串行写作，批次间并行执行。

### 主 Agent 流程

```
1. 计算批次分配:
   - 每批 5-8 章（根据总章数动态调整）
   - 批次间不重叠
   - 示例: 30 章 → 5 批 × 6 章
2. 为每个批次派生子 Agent（使用 Agent 工具，多个批次可并行派生）:
   - 每个 Agent 内部串行执行 [chapter-checklist.md](chapter-checklist.md) 的完整流程
   - 主 Agent 派生时必须将 prompt 中的 {skillBaseDir} 替换为 skill 安装根目录的绝对路径
3. 所有子 Agent 完成后 → 进入第四阶段：自动校验
```

### 子 Agent prompt 模板（并行模式）

> 派生前将 `{skillBaseDir}` 替换为 skill 安装根目录的绝对路径，`{start}`/`{end}` 替换为批次章节范围。

```
你是一个小说批量创作 Agent。你需要创作第 {start} 章到第 {end} 章。

## 项目信息
- 项目路径: {projectPath}
- 你负责的章节: 第 {start} 章 到 第 {end} 章

## 创作步骤
对每一章依次执行 {skillBaseDir}/references/flows/chapter-checklist.md 的完整流程（阶段 A-D），不得跳过任何步骤。

## 重要约束
- 不要使用 AskUserQuestion，不要向用户确认任何事
- **每章开始前必须读取大纲与任务卡**，严格按大纲的核心事件和悬念钩子创作
- **双源动态加权文风锚定（小说正文越多参考自身越重）**：动笔前必须读取 `03-文风基准.md` 与前序已定稿章节。严格遵循“文风不仅参考外部文本更深度参考小说正文，且正文越多参考自身权重越重”原则。将外部反模式禁令与本书已确立的黄金段落、上一章切片按动态权重混合装载，重点对齐本书已定型的人物台词质感与动作白描！
- **每章动笔前必须执行出场人员盘点与小传核查**：盘点本章出场人员。主角和配角都要有人物小传，理论上只要多次出现的人物都要设立小传。除纯一次性龙套外，所有角色必须先行补齐小传，按「02-人物/主角/」、「02-人物/配角/」、「02-人物/辅助角色/第{XX}章-[角色名].md」规范归类并登记。小传为性格与人物建立基础，正文无需全盘复述其生平，后续合规性校验（教研质检）将作为基准输入对照核查！然后再撰写正文！
- 字数必须达到 3000 字以上
- **每章必须过一遍去 AI 味四关（硬性前置）**：按 {skillBaseDir}/references/ai-tone/chapter-gate-runbook.md 执行，先跑 `python {skillBaseDir}/scripts/scan_ai_tone.py <章节路径> --project-dir {projectPath} --auto-report --json`，再逐关人工处理 G1 Humanizer-zh / G2 speak-human-tw / G3 shuorenhua / G4 lieflat，改完重跑至 block=0。任一关 BLOCKED 严禁进入事实回写
- **每章收尾前必须运行一致性核验**：执行 python {skillBaseDir}/scripts/verify_chapter_consistency.py <章节路径> --auto-report --json，深度核验多主角时间生命线、世界主线事件时刻表、情节因果与人设禁令，判定为 BLOCKED 必须重修至通过，并自动沉淀报告至 08-审稿/
- 共享文件（02-写作计划.json、99-章节摘要.md、02-人物/人物总表.md、设定词典）只用 Edit 工具更新且改前重读，禁止 Bash 整体重写
- 你负责的所有章节必须全部完成

完成后报告: 各章编号、字数、四维一致性核验结论（PASS）
```

### 并行写入协议

写作工具对并发修改有检测（文件在读取后被他人改动，Edit/Write 会报错强制重读），但 Bash 写入没有这层保护，报错重试也会浪费轮次。因此并行期间各批次必须遵守：

1. **写作计划**：每批只允许用 Edit 工具修改 `02-写作计划.json` 中**自己章节**的 `status`/`wordCount`/`wordCountPass` 字段；修改前必须重新读取 JSON（不要基于派生时缓存的旧内容 Edit）；**禁止用 Bash/脚本整体重写 JSON**
2. **章节摘要**：按各自章号小节追加到 `99-章节摘要.md`，同样只用 Edit 且改前重读
3. **设定词典与人物总表**：更新 `01-大纲.md` 设定词典或 `02-人物/人物总表.md` 只用 Edit 且改前重读；遇到持续报错，稍候重试，不要改用 Bash 追加
4. **跨批次衔接**：每批第一章动笔时，上一批末章可能尚未落盘——此时以大纲该章「承接上章」「悬念钩子」栏为衔接依据，不阻塞等待。全部批次完成后，主 Agent 对每个批次接缝做衔接检查（读前批末章结尾 + 后批首章开头），断裂处轻量修顺

## 4. 多 Agent 协作模式（writingMode: "agent-teams"）

**通用描述**：适用于宿主环境提供多 Agent 协作机制的场景（共享任务队列、Agent 间通讯、团队管理），需用户手动开启。**以能力描述为准，具体工具名称随宿主环境而定**——环境中有什么就用什么；不提供这些能力时，回退到「子Agent并行模式」。

### 主 Agent 流程

```
1. 用环境提供的团队/任务机制创建协作团队，并为每一章创建一个可认领任务（任务描述含章号）
2. 派生 3-5 个团队成员，下发成员 prompt 模板
3. 成员循环（环境工具随宿主而定）:
   a. 读取共享任务列表中的可用任务
   b. 认领任务（认领即独占，避免两人写同一章）
   c. 对该章执行 {skillBaseDir}/references/flows/chapter-checklist.md 的完整流程（阶段 A-D，含写前角色盘点与非一次性角色小传补齐）
   d. 标记任务完成
   e. 回到任务列表认领下一章
4. 所有任务完成后 → 关闭团队 → 进入第四阶段：自动校验
```

### 团队成员 prompt 模板

```
你是一个小说创作团队成员。按团队任务机制认领章节并创作。

## 项目信息
- 项目路径: {projectPath}
- 逐章清单: {skillBaseDir}/references/flows/chapter-checklist.md（阶段 A-D 不得跳步）

## 工作循环
1. 从共享任务列表认领一个未认领的章节（认领即独占）
2. 对该章执行逐章清单完整流程（重点：写前盘点参演角色，主角/配角/多次出现角色必须先补齐小传奠定性格基础，并作为合规质检输入，再写正文）
3. 标记任务完成，认领下一章，直到没有可用任务

## 重要约束
- 不要向用户确认任何事
- **每章开始前必须读取大纲**，严格按大纲的核心事件和悬念钩子创作
- 字数必须达到 3000 字以上
- 只通过团队通讯机制与其他成员协调，禁止写他人已认领的章节
- 共享文件写入遵守「并行写入协议」
```

**并发安全**：任务认领的原子独占语义保证一章只被一个成员写；共享文件（写作计划 JSON、章节摘要、设定词典、人物总表）的写入遵守「并行写入协议」。
