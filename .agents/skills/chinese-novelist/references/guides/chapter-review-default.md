# 单章正文质量审查·默认执行提示词

> **类型：执行模板，不是第二套评分协议。** 所有正文审查的权威判断、37项原始定义、评分阈值和优化边界以本 Skill 的 [review-core.md](review-core.md) 与 [ai-style-37-checks.md](ai-style-37-checks.md) 最新版本为准。本文件规定每次审稿任务必须实际走过的步骤、修订和验收输出，不能取代核心协议。不要重复叠加旧 G1–G4 等历史关卡。

## 0. 自动触发与参数

- 用户要求对**正式正文**进行「审核、审查、质量检测、检查、复审、去 AI 味、优化后复核」等，无论有没有粘贴审稿提示词，**必须自动读取并执行本模板**，不允许只依据名称打分或只跑机械脚本；对「检查第X章」等明确指向正式正文的短指令亦同。
- 目标由本次用户指令指定：`【卷号】`、`【章节编号或插章名】`；本模板里的示例“第一卷·第001章”只是默认参数示例，**不是固定目标**。没有明确章节但要求审查整卷／多章时，逐章执行本模板，再汇总跨章问题；不要用一次抽样冒充逐章已审。
- 用户只提交卷纲、章纲、章节简写、任务卡而非正文时，**改走 [outline-review.md](outline-review.md) 的剧情模式**，不套用正文37项语言检测，也不强制修改正文。混合任务分流处理。
- 用户本次明确“只审不改／只给意见”时仍走完整阅读与裁决，但禁止写回；其余主动质量审核按已有授权自动实施有正净收益的最小修改。不能自动决定的重大设定、人物命运与情节改动交作者裁决。
- 不创建 PR；有仓库写权限则在**当前工作分支**直接修改，按本次授权决定是否提交；没有本地脚本环境不能把远端写文件当成执行了本地校验。

## 1. 审查前：实际核对与登记

1. 确认当前项目、工作分支和文件版本。读取 `AGENTS.md`、`novel.project.json`、`SKILL.md`、`review-core.md`、正式37项清单、`paths.story_rules` 指定文风规范。
2. 按项目真实目录定位并阅读本章任务卡、卷大纲、章大纲、章节简写、关键情节任务卡、出场人物独立小传、世界观与势力/装备规则。
3. **完整读取**本章 MD 正文；定位对应单章 TXT、所在卷合订本。按必要性读取相邻章节、人物实时状态、编组、时间线和伏笔记录，核对跨章连续性。
4. 严格区分**已写入正文的已发生事实／确认设定／未经批准的规划／角色或审稿者推测**。发现冲突追溯权威来源和生效时间，不用最近时间戳粗暴覆盖已发生事实。
5. 登记真实读取的文件、分支/版本、读取范围及缺失资料。没有读到的文件不得声称已核对；无法充分读取时不可给伪精确分或虚报 PASS。

## 2. 剧情层独立审查（先于语言评判）

对每个主要场景核查：**目标→信息与证据→人物选择→实际行动→真实后果**，不要求机械套模板，但事件因果须成立。

- 人物动机、身份、能力、立场、当时知情边界、群像独立判断及关系发展是否可信；是否为了剧情让对手降智、让人物凭空知道答案。
- 时间、地点、路线、空间、战术命令、观察报告、装备弹药、物资、伤病/体力、指挥与编组、世界规则是否自洽。
- 场景是否新增事件、风险、关系、情绪质感、代价、情报或伏笔；是否同构重复、巧合解围、无代价选择、机械反转或突然揭示。
- 开篇即时问题、过程阅读动力、场景节奏、信息释放、章尾悬念与追更吸引力是否有效；不能为造钩子强改事实或增加不合理危机。
- 记录剧情问题与最强合理反证；**不调用简写专属七维表为正式正文重复评分**。

## 3. AI 味37项逐项、逐段深审（本次最高优先级）

从 `ai-style-37-checks.md` 读取**完整37条**，每项逐一裁决；重点复核第32—37项：程序化、公文式绕弯；免责腔/冗余否定；多人声口同质化；翻译腔及指代语序；模板句/虚假叙事增量；重复/机械修辞节奏。不得自行增设第38项。

**必须通读每个自然段，结合相邻段落和完整场景做语义检查，禁止仅扫关键词。** 每段逐点核问：

1. 此段实际新增了什么事件、人物关系、情绪、信息、风险或有效伏笔？删掉某句话，会否真的损失这些内容？
2. 低头、沉默、移开视线、按纸、停顿等微动作是否符合现场行为目的，还是用微动作伪造叙事意义？
3. “不是……而是……”“没有……只是……”及机械对仗/排比是否推动真实理解，还是制造假深度？
4. 是否用抽象概念代替具体选择、动作和实际后果？是否在段尾不必要地解释心理、主题和象征？
5. 是否连续多个段落重复“动作→解释→结论”、同类句首句尾、同一修辞和停顿节奏？
6. 中文语序、中心词、指代、搭配、动作主体与句间关系是否自然；是否一句能讲清却绕成多句，迫使读者回读？
7. 是否存在不必要的免责声明、公文流程复述、背景复读、修饰副词堆叠或翻译腔？

**人物对白逐句专项**：先确定说话人，再按其身份、性格、文化程度、职业、情绪、权力关系、现场目标和知情边界检查。严查多人共用完整书面逻辑、责任宣言、抽象格言、密集比喻、公文腔和过度工整的台词。连续阅读同场多人的往来，不能摘孤句判错。

**必须同时寻找反证**：真实战术军令、专业手续、人物口头禅、有目的的重复、有效留白、慢场景、必要的不确定性、能体现人物的简洁或特殊句式不得机械删除。不要以 AI 特征推断作者身份或编造生成概率。

每条规则裁决仅使用：`不明显／待复核／明显／证据不足／不适用`。记录规则编号、具体正文定位和短引文、上下文、阅读损害、最强反证、裁决；不适用写明原因。**同一根因可关联多个规则，但只记一个真实问题、只扣一次分。**

## 4. 独立反方审阅与主审复核

有真正可用的独立子智能体时，在主审最终定案前发起**独立阅读**，不预先发送主审评分或修法；要求反方给出有证据的最多3—5处有力质疑、每处最强反证、值得保留的有效原文，且反方不得直接改稿。主审对每项裁决 `成立／部分成立／被推翻／待核实`。

不能真实派生子智能体时，改为**单模型隔离式反证审查**，明确写“非独立子智能体审阅”。没有真正运行的审阅/第三方工具不得标“已完成”。

## 5. 两套验收：正文评分与 AI 味专项分开

正文七维每项0—10分，按项目权重计算百分总分（改前、改后都使用同一量表）：

| 维度 | 权重 |
|---|---:|
| 剧情因果与信息证据链 | 20% |
| 时空、物理与战术合理性 | 15% |
| 设定、装备与跨章连续性 | 15% |
| 人物动机与群像真实度 | 15% |
| 节奏、可读性与追更欲 | 15% |
| 语言自然度与 AI 式模式控制 | 15% |
| 悬念、伏笔与信息释放 | 5% |

总分＝Σ(分项得分×该项权重÷10)。篇幅不参与文学分；机械检测不等于人工评分。文学 `BLOCKED` 仅针对确证的实质 P0/P1；工程交付、AI 味专项另判断。

AI 味37项**单独验收，不再加权**：仍有“明显”＝`不通过`；无明显但仍有“待复核/证据不足”＝`未完成/待核实`；充分检查且全部适用项均“不明显”＝`通过`。不得因为质量总分高或扫描 PASS 就宣称 AI 味通过。

问题记录至少含：编号、P0—P3、原文定位/短引文、真实阅读损害、反证、最终裁决、最小修法、收益与损害、实际改动和复验状态。

## 6. AI 味疑点主动核实 + 净收益自动修订

- **明显**：必须主动寻找净收益为正的最小改法，直接修改并复验；无安全有效改法则登记未解决，不可虚报通过。
- **待复核**：必须回到真实原文、上下文、人物声口和任务资料补证；成立/部分成立且净收益为正则修改；被反证推翻则改判“不明显”并保留；仍无法确认则登记阻塞，不可跳过。
- **证据不足**：必须主动查询缺失资料并尝试定案；证据仍不足就说明具体缺什么、为什么无法核实，不凭空改稿。
- **不明显**：保留，不作无意义美化；**不适用**：不修改。

**只有核实过并裁决“不明显”或“不适用”的项能直接跳过修订处理。** 但“必须处理疑点”不等于“强行改写每条嫌疑句”：确证问题没有正收益修法也不得改坏原文，须登记为未解决。

每项方案先比较：**收益**（自然中文、对白真实、信息清晰、叙事增量、因果准确）与**损害**（人物声口、真实手续、必要留白、情绪积累、伏笔、知情边界、时间/设定）。仅净收益明确大于损害才允许落笔。按**词语→句子→邻句→局部段落→必要场景局部**优先修改；禁止无收益整章重写、制造另一类 AI 模板或补造角色背景和装备。

逐项记录真实的“改前→改后”、位置、理由、收益、风险、验证和回滚。改差必须回滚，回滚尝试计入优化轮次；不得为凑次数强改。

## 7. 单章最多5轮优化闭环

与 [review-core.md](review-core.md) 一致，优化轮次按**单章**计算，分数闭环和 AI 味专项独立验收：

- **初分 >80**：实施**一次**正收益优化并复验后结束。
- **初分 75—80（含两端）**：实施**一次**正收益优化并复验后结束。
- **初分 <75**：反复“优化→同量表复审”，首次复审**>75**后补一次正收益优化，再复验结束。
- **总优化次数至多5轮**（包括末次补优化和回滚的尝试）；到达上限、没有正收益方案、资料不足或遇重大作者待决事项时停止。第5次才超过75但无法再补优化，也不得做第6次。
- 正文评分达到结束阈值并**不自动宣称 AI 味专项通过**；在协议允许的轮次内优先消除确认的 AI 味问题，若仍有问题则按实际状态报告，不能借专项理由突破一次/五轮的现行上限。

## 8. 复验、同步与真实执行边界

每轮改后复读修改句段和相邻场景，重新裁决受影响 AI 味规则，查对白、剧情、人物声口/知情、战术、伤病、装备、必要邻章和伏笔；发现新问题或净损害则回滚。

以 `06-正文/` 下 Markdown 为**唯一正文源**，修改后按项目正式脚本同步单章 TXT 与分卷合订本，检查标题、顺序、字符内容、自然段和场景空行；使用可运行的工程脚本验证，例如：

```bash
python .agents/skills/chinese-novelist/scripts/export_reading_txt.py --project-dir . --chapter "06-正文/实际卷/实际章节.md"
python .agents/skills/chinese-novelist/scripts/export_reading_txt.py --project-dir . --all --check
```

全量导出是否需要 `--all` 依项目脚本及合订本行为判断。**没有实际运行脚本，就不能报告同步检查 PASS**；若仅有 GitHub 文件 API 或其他有限权限，逐项写明已更改内容、尚未执行的导出与检查，不能把设计或预期当作已落盘。

## 9. 审稿记录与最终回复

若项目已有审查报告归档路径，沿用其规范；不要制造第二套重复报告。完整报告保留：

1. 实读文件/版本/范围、缺失资料、工具执行状态与反方方式。
2. 剧情问题与证据/反证/裁决。
3. 改前改后七维分项及总分。
4. 37项规则**逐项裁决**（包括“不明显/不适用”）、重点段落证据。
5. 反方攻击、最强反证与主审采纳/推翻情况。
6. 最小修改的收益/损害、改前改后、实改/保留/回滚和轮次。
7. MD/TXT/合订本实际同步与检查命令结果。
8. 作者待决及未解决问题。

AI 味统计必须区分“规则项数”和“问题落点数”，记录初审明显/待复核/证据不足、实际修改数、复验解决数、反证推翻数、最终剩余数。

**对话最终回答**按顺序给出：①实际执行范围与反方方式；②剧情裁决；③完整七维改前/改后评分表；④AI味专项（逐项展示所有仍为或曾为“明显/待复核/证据不足”的项，附原文短引、影响、反证和结果；其他项留完整报告）；⑤反方裁决；⑥收益—损害评估；⑦真实改动及回滚；⑧文学质量、AI味专项、工程交付、MD/TXT/合订本同步分别验收及待作者裁决事项。

**不得虚报已读、已改、已提交、已运行脚本、独立子智能体完成或文学/工程 PASS。发现无问题要明确保留，不制造问题。**
