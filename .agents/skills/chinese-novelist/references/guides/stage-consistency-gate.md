# 四阶段成果物·相邻上游一致性硬门禁

> 最后修订时间：2026-11-06 12:20:41 +08:00
>
> 本文件是四阶段**审核结论的硬性判定规则**，不是独立质量评分表。由 chinese-novelist/SKILL.md 统一调用，规划评分沿用 outline-review.md，正文评分及 AI 味沿用 review-core.md。**发现确证的实质不一致，立即打回，不得被总分、作者历史审核结论或其他质量优点抵消。**

**注意：**本文件负责**写成后的相邻上游一致性验收**；创作之前还必须独立执行 [stage-entry-gate.md](stage-entry-gate.md) 的三项上游“审核通过”写作准入：卷纲通过才可写章纲、章纲通过才可写简写、简写通过才可写正文。下游一致不等于上游曾经审核通过，二者均不能互相替代。

## 1. 比对链与对象

| 本次审核对象 | 必须对照的直接上游 | 主要对照内容 |
| --- | --- | --- |
| 全书大纲（阶段一） | 作者已确认的全书核心意图、结局约束及项目权威世界观、人物主档、已发生事实（如存在） | 已锁定主线、角色命运、世界规则与全书目标；本阶段不存在“更早一层的作品大纲” |
| 卷纲（阶段二·卷级） | 已确认的**全书大纲／全书主线** | 本卷定位、卷级目标、人物命运窗口、主线推进、关键事件、阶段结果、跨卷承接、不能提前揭示或改变的事实 |
| 章纲（阶段二·章级） | 当前卷**有效、已确认的卷纲** | 必须落实的事件、人物、起因、冲突、决定、结果、代价、事件先后、伏笔、卷首钩子及各章职责 |
| 章节简写（阶段三） | 该编号章／独立插章的**有效章纲** | 本章关键场景与事件、目标、人物动机和选择、因果链、结果与代价、章节定位、需保留的伏笔及承接 |
| 正式正文（阶段四） | 该编号章／独立插章的**有效简写** | 已约定的主要行动、冲突、人物决定、情节顺序、结局、代价、信息揭示和章节功能 |

同时核对已发生正文事实、人物/世界权威设定、相邻卷章、作者最新明确决定，但它们是**交叉约束**，不可代替上表规定的直接上游对照。阶段二的卷纲和章纲虽归同一个创作阶段，审核时仍必须分别完成“全书大纲→卷纲”和“卷纲→章纲”两道核对。整卷、多章或插章按实际章节映射逐篇比较，不得抽样；先核对编号、章名、卷归属、插章插入位置及版本，禁止将生成索引或停用稿当作权威上游。

## 2. 证据矩阵与比对方法（必执行）

1. 从项目配置和当前权威目录定位**本次成果物与直接上游的完整当前有效版本**，登记文件路径、修订时间/确认状态、具体章节、读取范围。上游还包含多个卷级细纲、补充设计、作者锁定决议时，先按项目权威与修订时间规则归一，不能只挑有利的一份。
2. 建立逐项对应表：**上游具体位置/承诺 → 下游具体位置/落实 → 判断 → 证据/反证 → 处理方向**。至少核查角色、在场与知情、时空先后、核心事件、起因/动机、关键抉择、冲突与阻力、结果/代价、伏笔揭示/回收、章节功能与跨章交接。某项本就不适用可注明，不得臆造。
3. 对照**语义与因果**而非字面或事件数量。下游增加气氛、细节、对话、合理过渡、配角互动及不改变承诺的次要事件，通常是**一致的合理扩写**；章节合并/拆分或事件跨章移动只有存在明确生效的规划调整与来源可追溯，才算授权变更，不能擅自默许。
4. 逐项裁决为 `一致`、`合理扩写`、`已批准变更且上下游已同步`、`实质不一致`、`资料不足待核实`。实质不一致包括：**关键必写事件缺失或被弱化到失去功能；人物命运、动机、立场或关键决定改变；核心因果、结果与代价被改写；事件发生时点/顺序使其他情节不成立；提前泄露或改变锁定伏笔；卷/章主线被另一个故事取代；未经批准移走情节、改章职责或改变开卷钩子。**无凭据不能仅因表达不一样判不一致。
5. 找到不一致先核实作者是否**明确批准变更**、上游是否已同步生效，以及该调整是否违反更高权威或已发生正文。旧版本、作者尚未确认的建议和废弃草稿不作驳回依据。若作者批准**下游新方案但上游尚未同步**，仍然是未闭合的流程冲突；须按授权先同步上游并重新比对，不能以“作者同意过”跳过一致性验收。

## 3. 一票打回与停止条件

- **任一确认的实质不一致 → 本篇/本卷阶段审核结论 `打回／不通过`，禁止标为 `PASS`、`质量通过`、`可进入下一阶段` 或 `已完成阶段验收`。**即使16维/七维评分达到80、90分，或AI味专项全部通过，也照样打回；得分仅作独立诊断，不得冲抵硬门禁。整卷含任意一篇打回，整卷总体不得报全卷通过，未涉篇目可单独记录结果。
- **直接上游缺失、未确认、被停用或无法完整读取 → `一致性待核实／阶段验收暂缓`，不得虚报一致，更不可因找不到对照物便给 PASS。**应实际审核可读下游材料、如实报告可评的质量及缺项，但不能宣布完成相邻一致性审核；这不是已证实的不一致，不得错贴“打回”的事实标签。
- 上游与已定稿正文/更高权威冲突，或新旧有效版本尚无法裁决时，标记**需作者裁决／阶段验收暂缓**；不得直接凭下游更精彩而自动改上游，也不得因为上游文字更早而机械推翻已发生正文。作者明确允许带缺项**继续创作**不等于允许**审核通过**。
- **修复优先级**：一般情况先修改下游使其符合现行上游；确需改变锁定剧情、人物结局、卷/章编排或已发生事实，先请作者批准调整并明确回溯范围，再依法更新上下游与相关派生索引。正式正文只能在已有授权及正收益边界内定向修改；不可为了通过门禁擅自重写大段已定稿正文。前三阶段审核仍默认只读。
- **复审闭环**：修改后重新完整比对受影响项与邻章/跨卷承接，所有 `实质不一致` 消除且上游证据完整，才可把一致性改判为通过；单靠重新评分、改写报告结论或修改下游但未同步规划均不算修复。评分后的自动优化不得绕过此门禁。

## 4. 审核报告必填项

每份四阶段审核报告必须有独立的“**相邻上游一致性验收**”章节；全书大纲按阶段一的权威约束核对。至少写：

- **对照对象与版本**：本次稿、直接上游、具体卷章/插章、文件路径、有效状态和修改时间，缺失项及实际覆盖数量；
- **逐项映射表**：上游原文短摘或准确提要及位置、下游原文短摘或准确提要及位置、判断、反证、需改什么，整卷逐章列出；
- **硬门禁结论**：`通过` / `打回（不通过）` / `待核实（暂缓）`，列出每一处打回证据、应改文件及谁有权批准；质量分、AI味和工程结果保持独立；
- **复审证据**：实改范围、哪些文件版本已同步、复审对照结果、仍存冲突与不能安全自动改的内容。

报告、进度台账和适用的正文终审总表必须反映真实的 **`打回／不通过` 或 `待核实`**，不得因为总分达标、历史记录“已审核”、作者已确认写完，自动把当前版本标为合格。没有实际报告、版本对照或验收脚本时，不虚报已验证；台账字段按现有正式口径记录，不引入“上游一致性分数”。
