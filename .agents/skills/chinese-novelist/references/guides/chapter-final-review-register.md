# 章节最终审核总表维护规范（正文审核的记录层）

> 本文规定**怎样持久记录每章已经完成的审核结果**，不是新的质量量表、独立审核关卡或免审捷径。质量评分、AI 味37项裁决、P级、复审与门禁以 [review-core.md](review-core.md) 为唯一依据；执行步骤以 [chapter-review-default.md](chapter-review-default.md) 为准。不得用统计表反向篡改正式审核报告。

## 1. 启用时机与位置

- 对正式正文完成一次有证据的审查/复审并形成报告后，**同次交付内维护总表**；包括单章、多章、整卷批量审核，以及以后再次复审的同章记录。仅讨论表格、仅审纲要/简写时不产生正式正文评分记录。
- **优先沿用项目已有、已指定的审核总表与审稿归档目录**，不得另造一套同名权威文件。项目尚无总表时，在项目真实的审核报告目录建立 `章节最终审核总表.xlsx`；本仓如使用 `08-审稿/` 归档，则位于 `08-审稿/章节最终审核总表.xlsx`。禁止把该示例目录硬编码为其他作品的默认目录。
- 推荐同目录维护 `章节最终审核总表.csv` 作为可做版本差异对照的**机器可读镜像**；如建立镜像，必须和 XLSX 使用同一批已核实数据，禁止双主档相互冲突。已有系统采用 CSV、数据库或其他表格作唯一来源时，优先服从项目配置，由来源生成 XLSX 展示副本，不反向手工改写来源。
- 本规范只定义应写什么及如何核验；**不意味着当前环境已经创建、打开或更新文件**。仅有 GitHub 文本编辑能力而无法可靠写入 XLSX 时，先按实际权限维护项目认可的文本来源（若存在），并将“XLSX 未同步/待补”明确列为交付阻塞；不得宣称表格已更新。用户当次明确“只读/只审不改”时不得写回任何总表，说明未更新即可。

## 2. 数据结构（每个正式篇目一条当前结果）

唯一键：`作品标识 + 卷标识 + 篇目标识`。编号章与不占编号的插章分别编号，不能合并；同章反复审稿**更新该行**，不在主表新增重复行。为保留审稿历史，历次报告和必要时独立的“审核历史”工作表记录每轮的报告路径、版本及日期，而非无限增列分数。

| 分类 | 字段（建议列名） | 规则 |
|---|---|---|
| 定位 | 作品、卷号、章节号/插章标识、章节标题 | 使用项目真实正式章节标识和标题；不从计划稿猜测 |
| 证据 | 正文源路径、正文版本/校验值、最终审核报告路径、最终审核时间 | 尽可能记录可追踪的提交 SHA 或文件版本；无证据则空置/标未核实 |
| 评分 | 初审总分、最终总分、分数变化 | 均为**正式正文七维加权总分**，范围0—100、至多1位小数；`变化 = 最终 - 初审`，不同量表历史分禁止直接相减 |
| 七维 | 剧情因果、时空行动与物理合理性、设定及跨章连续性、人物群像、节奏可读性、语言自然度、悬念伏笔 | 记录**最终复审**每项原始0—10分，必须与报告和唯一核心协议权重一致，不重新发明类别和算法 |
| AI 味 | AI味专项结论、最终明显项数、最终待复核项数、最终证据不足项数、37项裁决报告链接 | **不设“AI味分数/百分比/AI生成概率”**；专项结论只能按核心协议为“通过/不通过/待复核（待核实）” |
| 问题闭环 | 初审确证问题数、确认修复数、最终遗留问题数、最终P0/P1数、遗留问题摘要 | 依正式报告的实质问题落点统计，同根因只记一项；区分规则项数与问题数 |
| 结论 | 文学质量结论、工程交付结论、总体验收状态、反方审阅方式 | 文学按 `PASS/BLOCKED/待核实`，工程按项目门禁；总体验收仅汇总，**不产生新质量门槛**；独立反方与单模型反证不得混写 |
| 交付 | 正文同步状态、适用阅读副本/合订本状态、阻塞事项 | 副本不存在则“不适用”；存在但未验证则“未验收”；不能以写入正文推定TXT或合订本同步 |
| 追踪 | 最近修改/复审日期、备注 | 记本次更新及尚待作者裁决事项；必要时引用历史报告 |

**正式正文七维固定权重**：剧情因果20、时空行动与物理合理性15、设定及跨章连续性15、人物群像15、节奏可读性15、语言自然度15、悬念伏笔5。各项原始分0—10；`总分 = Σ(原始分 × 权重 / 10)`，最多一位小数。不得与只用于卷纲/章纲/简写的另一套七维混用。AI味专项依37条规则独立裁决，**不计分**。

## 3. 工作簿结构与统计口径

建议一个 XLSX 包含以下工作表：

1. **章节总表**：每章一行；首行冻结、筛选可用、分数用数值而非拼接文本；空分数保留空值，不写0冒充未审；有链接的字段可直接定位原报告。
2. **分卷统计**：按卷统计纳入总表的篇目数、已完成有效复审数、文学通过数、AI专项通过数、工程已验收数、最终平均/最高/最低总分；**均分分母仅计有真实有效最终总分的记录**，不拿未审章节或空值计算。
3. **待复核与低分章节**：按证据不足、遗留P0/P1、AI专项未通过、工程不同步和最终总分升序筛选；可列全书/各卷**最终总分最低5章**及**语言自然度最低5章**，不可伪称存在AI味专项分数排序。低分排序是检索辅助，不代替核心协议P级或AI味结论。

如项目已有更完整的统计表，可复用而非强制添加重复工作表。Excel公式、统计、排序或颜色只是展示；不能覆盖人工语义审稿结论。

## 4. 单章更新事务（报告落盘之后）

1. **确认来源**：以本次真实读取的正式正文、对应审核报告和复审证据为依据；标注源稿版本、最终复审轮次、原始七维、AI味37项裁决、P级及当前工程交付结果。
2. **保持一章一行**：按唯一键查找并更新；首次审查才新增。若同一章不同审核报告冲突，先核实目标版本和复审先后，不能用时间戳替代内容确认，也不能把旧版本较高分数覆盖新版本的已验证结论。
3. **分数可追溯**：初审分取本次闭环的基线，最终分取**最后一次实际完成的文学复审**；最后一次修改后若未复审，不沿用修改前分数标为“最终”；初审/复审任一缺证，留空并说明，不补猜测数字。
4. **状态各自独立**：文学、AI味、工程、正文及副本同步分别记录。总体验收标“通过”需有对应全部适用状态真实满足的证据；任何明确阻断记“不通过/阻塞”，尚未核验记“待复核/未完成”，避免将高总分当作自动PASS。
5. **核查和保存**：检查键无重复、七维加权重算与报告一致、总分变化一致、AI专项没有数值分、未审章不计均分、报告链接有效、适用副本状态未虚报；**先保存主数据，再生成/校对展示副本与统计**。若写回失败，保留原有效文件、不制造部分成功说法，交付时报告未同步的具体文件。
6. **输出摘要**：最终答复增加总表实际路径、更新了哪些篇目、更新前后来源版本、XLSX/CSV实际写入和校验状态及任何阻塞。不得拿总表替代逐章审查报告或逐段覆盖证据。

## 5. 边界和复审历史

- **只审不改正文 ≠ 可以偷偷改总表**：若用户的只读限制涵盖仓库写入，则总表也不写。若用户仅禁止改正文但允许保存审查记录，则可以依据明确授权记录审核结果。
- 审核被中断、工具不支持、正文不全、反方审阅降级、工程副本未验证等必须在可验证的字段如实体现；仅少数步骤完成不能写“全流程完成”。
- 旧量表历史评分不得机械换算为新版结果；需重新实审才能有正式新版最终分。避免为填满总表对从未审过的章节造分。
- 修改方案、37项逐项裁决、完整改前/改后证据及历史轮次以**各章审核报告为准**；总表只是导航与查询索引。其它小说沿用此通用流程，但所有名称、目录和状态来自对应作品配置。
