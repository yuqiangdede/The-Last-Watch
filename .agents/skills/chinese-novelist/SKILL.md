# chinese-novelist（精简入口）

本 Skill 包含创作、规划、写后工程验收与质量审稿。**正式正文的唯一质量评分规则**见 [review-core.md](references/guides/review-core.md)，规划阶段的评分规范见 [outline-review.md](references/guides/outline-review.md)；**四阶段审核结论另须执行 [相邻上游一致性硬门禁](references/guides/stage-consistency-gate.md)，不新增质量分项但确证实质不一致直接打回**；**创作前必须执行 [上游审核通过写作准入门禁](references/guides/stage-entry-gate.md)，未通过不得生成下游新稿**；对话插件 `novel-quality-review` 使用相同核心协议。原 G1—G4、S、F、TR/TX、PAM、朱雀、场景自然度、六类重复等**归并为五类同轮检查**，不再作为额外强制逐项加载/逐关打分；旧文档、源案例、研究和脚本保存在 references/ 与 scripts/，仅在遇到对应疑点时查阅。不得因同根因多次扣分。

## 设定维护专项入口（手动）

当作者要求“清理设定冲突、同步过期设定、全书卷纲章纲一致性检查”时，执行仓库同级 [novel-setting-maintenance Skill](../novel-setting-maintenance/SKILL.md)，不得把四阶段质量评分当成设定冲突裁决。该专项全量核验人物、世界观、卷纲、独立卷级细纲、全部逐章章纲、任务卡和动态记忆。**正文、TXT与章节简写只读，不得借设定清理擅改。**只手动执行，无定时触发；通过证据确认的安全修复遵循本 Skill §1.1 修订时间规则及作者重大变更权限。机械脚本不能替代语义审阅。

## 跨作品隔离原则（强制）

**本 Skill 只保存通用方法、通用流程与可选的跨题材示例，不得包含任何单部小说专属的角色姓名、地点、势力、事件安排、固定卷数、武器部署、战术方案、技术参数或指定文风。** 特定小说的叙事视角、声口、情节走向、职业／军事／奇幻等专项限制，只能存放在该小说项目自己的权威文件中，并由项目配置（如 `paths.story_rules`）显式加载。通用示例不能成为默认写作规则或评分依据；未确认的内容不能从本 Skill 推断或补造。

## 四阶段创作进度台账（每次写作／审核后必更新）

本项目通过 [novel-progress-ledger](../novel-progress-ledger/SKILL.md) 统一维护20卷、每章及不编号插章的**卷纲、章纲、章节简写、正文**四阶段成稿和审核状态。主视图为 `05-写作计划/创作阶段进度.md`，CSV镜像为 `05-写作计划/创作阶段进度.csv`；单条正式阶段审核事件在 `05-写作计划/阶段审核记录.json` 留证据、结论、评分和报告路径。写完不等于审完，已审不等于审核通过；作者历史确认状态、得分高、旧版通过都不能替代当前有效上游的正式审核通过记录；AI味37项不打数值分。

**强制事务**：四阶段任一成果物新建/修订/删除或章纲重排后更新进度表；阶段一至四真实完成一轮审核并有正式报告后登记对应卷／章及稿件SHA256、报告、结论、分数，再生成/校验表格。正式正文先维护已有章节最终审核总表及报告，再刷新阶段台账；无报告不允许编造审核分数。不能运行生成脚本时要明确说明本轮同步阻塞，不得报告检查通过。只读审核且明确禁止仓库写入时不写台账。本流程禁止自动修改 `07-创作记忆/作者人工复核进度.md`。

本项目命令：`python .agents/skills/novel-progress-ledger/scripts/update_progress_ledger.py --project-dir .`；验收在其后加 `--check`。详见上述进度 Skill，严禁将本作品的20卷、中文路径或人物名称写成通用 Skill 硬编码规则。

## 0. 审核请求自动调用（默认入口，必执行）

**只要用户要求对正式小说正文做“审核／审查／检测／检查／复审／去AI味／质量优化”，即使只说“审核某章”或“检查某卷”，也必须自动读取并执行 [通用单章正文审查默认执行模板](references/guides/chapter-review-default.md)，再按 [唯一核心审查协议](references/guides/review-core.md) 与 [37项规则原表](references/guides/ai-style-37-checks.md) 裁决。用户无需重复粘贴提示词。** 一次多章/整卷请求按实际可读范围逐章执行并汇总跨章问题，禁止以抽样代替全卷审查。审查目标、编号和文件路径由当前作品配置及用户指令决定，模板不绑定任何固定作品、卷数或文风。

- **四阶段任务分流**：全书大纲、分卷章纲、章节简写及正式正文分别调用第0.1节的独立提示词；规划阶段按 [剧情审查](references/guides/outline-review.md) 的阶段量表，不套正文语言37项；混合请求分开报告。
- **审核权限分流**：阶段一至三规划审核默认只审不改成果物，本次明确授权后才可修订；**阶段四正式正文主动审核**未指定只读时依模板执行证据核查、反证、正收益最小修改及复验，轮次与阈值以 `review-core.md` 为准。重大情节变更、权限不足及证据不足须停止不安全改写并交代阻塞。
- **真实工具边界**：没有真实子Agent时只能做单模型反证；没有读到完整原文或运行项目需要的导出/验证流程时，不得宣称相应审阅或同步验收完成。版本控制按当前项目和本次用户要求执行，不将本仓库的提交、PR偏好当作 Skill 通用规则。
- **协议关系**：默认模板是**每次执行步骤的入口**，并非新一套评分体系；核心协议是唯一质量判定规则，旧四关、词频和研究案例按需查证，不重复强制加载或重复扣分。

**正式正文必检 META-01（叙事出戏与元叙事泄漏）**：同轮逐段检查卷章引用、作者/读者口吻、人物小传或大纲泄漏、旁白解释伏笔及创作功能、无关键词的作品外解说；按核心协议复核叙事视角、故事内部卷宗、人物回忆与有意元叙事的反证。逐章记录覆盖、证实/排除、实际修订。不是 AI 味第38项，不新增评分或重复扣分。

## 0.1 四阶段审核提示词索引（按用户指定的成果物自动切换）

**强制比对链**：卷纲↔已确认全书大纲，章纲↔该卷有效卷纲，简写↔该篇有效章纲，正文↔该篇有效简写；全书大纲对照作者确认的核心主线/结局和权威设定。四份审核提示词均须引用 [stage-consistency-gate.md](references/guides/stage-consistency-gate.md)，按卷章/插章逐项语义核验并独立出具一致性结论。**确证实质偏离一票打回、不得进入下一阶段；对照资料缺失/无法确认则暂缓验收，不得标通过；合理扩写不算不一致。**上游与已发生正文或作者新决定冲突先裁决版本，不准静默改写已发生事实。


| 审核对象 | 指定提示词 | 唯一评分标准 | 默认行为 |
|---|---|---|---|
| 全书大纲／全书总纲 | [阶段一：全书大纲](references/guides/review-prompt-01-book-outline.md) | [outline-review.md](references/guides/outline-review.md) 16维100分 | 只审不改 |
| 分卷章纲／某卷章纲／单章章纲 | [阶段二：分卷章纲](references/guides/review-prompt-02-volume-chapter-outline.md) | 16维100分，按实际粒度 | 只审不改 |
| 章节简写／独立插章简写 | [阶段三：章节简写](references/guides/review-prompt-03-chapter-brief.md) | 剧情七维100分 | 只审不改 |
| 正式单章、多章及整卷正文 | [阶段四：正式正文](references/guides/review-prompt-04-chapter-prose.md)＋[正文默认模板](references/guides/chapter-review-default.md) | [review-core.md](references/guides/review-core.md) 正文七维＋AI味37项（专项不计分） | 按项目授权正收益自动修改 |

可以直接要求“审核全书大纲”“审核第四卷章纲”“审核第四卷第128章简写”“审核第四卷第128章正文”；不必重复粘贴整份提示词。用户只说“审核第X章”，以项目定位的正式正文为默认对象；定位不明确时需核实卷号、全书/卷内编号或是否指简写，不能混淆。审核既有产物时允许披露前置缺失，不因历史缺项直接拒审；**新写作跨阶段**仍按第2节提醒。

**章节简写逐篇80分硬门禁（2026-11-06）**：阶段三每一篇编号章及不编号插章，均须按唯一剧情七维100分量表**独立得分≥80**，才有资格取得“审核通过”并进入正文；**整卷均分、卷纲/章纲高分或其他篇目高分均不能替任何一篇补足分数**。任一篇得分不足80须登记“不通过”，作者授权下定向修订并对**修改后的当前文件**独立复审，直至≥80；同时仍必须满足章纲→简写一致性、无未解决P0/P1、证据与版本门禁。80分只是必要非充分条件，不另创量表、不用分数覆盖实质冲突。

**一致性不是评分维度**：无论规划16维、简写剧情七维还是正文七维评分有多高，均不得覆盖“相邻上游一致性验收”的打回或待核结果；审核报告与阶段台账必须区分“审核已执行”和“审核通过”，正文的 AI 味、文学与工程也分别记录。

**评分与证据隔离**：每次重读当前成果物，独立核实与评分；允许旧问题清单作为待核线索，**不得引用、复制或参考以前的评分**。同一轮初审与修改后复审可比较。规划16维、简写剧情七维、正文七维互不换算，正文AI味37项不是数值分；开篇前3章/前10章专项只能在有实际章级材料时完成。

## 1. 项目定位与权限

1. 先确定当前项目根目录，读取 `AGENTS.md`、`novel.project.json` 和用户指定的最新权威资料；依 `paths.story_rules` 加载项目约束。配置不存在时仅使用通用默认，不把任何示例书的人物、地名、参数、情节和卷数当成事实。参阅 [项目配置](references/guides/project-config.md)。
2. **已定稿正文是“已发生事实”，人物档案/世界观/卷纲是“确认约束”，未获批准的章节计划只是“待发生”**。遇到设定冲突先追溯双方来源、确认状态与修订时间，依第1.1节判定新旧版本；同等权威级别下，以**修改时间更晚且已获确认**的设定为准，不以新草稿覆盖权威设定。若新设定与已发生正文相矛盾，须核实作者是否明确批准追溯修改及同步范围，不得擅自改写历史事实。
3. 主角、核心配角及会反复登场且推动剧情的角色建立人物小传；小传作为行为/背景验证依据，不应全文倒灌到正文。分级归档参考 [人物创建](references/guides/character-building.md)。仅在当前作品涉及相应题材时加载历史、专业职业、医学、军事、科幻、奇幻、法律等专项，不预设必有任何一种题材要素。
4. 用户要求纯审核/讨论或明确“不修改”时只读；用户主动提出“质量审核/审查/复审”按下方闭环执行有正收益的小范围改稿；提交、发布和无法自动裁决的世界观修订仍依用户授权边界。

## 1.1 设定与规划的修订时间及新旧版本裁决（强制）

**任何设定、人物小传、全书大纲、卷纲、章纲发生实质改动，必须留下可追溯的修改时间和修改内容；新建、补充、删除、改写、迁移同样适用。** 世界观、人物关系、势力与能力规则、剧情因果、关键事件、章节简写及关联任务卡等承载上述信息的正式资料，一并执行。此规则适用于四阶段创作、审核后授权修订、事实回写和派生文件同步，不能因“顺手小改”跳过。

1. **每份文件标注最后修订时间**：在文档已有元数据区更新 `最后修订时间：YYYY-MM-DD HH:mm:ss ±HH:mm`；没有元数据区的 Markdown 在标题附近增设该字段。以**实际写入的时间**为准，统一使用项目约定时区并显式写出 UTC 偏移（未约定时使用北京时间 `+08:00`），不得用文件系统修改时间、聊天日期或 Git 提交时间冒充内容修改时间。只读审核不更新此字段。
2. **逐文件仅保留最新修订**：在文件末尾维护 `## 修订记录`（已有同类章节则沿用），每次实质修改更新唯一一条，至少写明**精确修改时间、修改位置或设定项、原设定→新设定的关键差异、修改原因、依据/确认来源及确认状态（已确认／待确认）**。可在同次修改的一条记录内分列多个相关改动，但不能只写“优化内容”“更新设定”等无法辨别新旧的笼统描述。**现行文档仅保留最新一条修订记录，每次有效变更覆盖前一条；被替换的旧记录通过 Git 历史追溯，不在文中重复累积。**确需纠正历史错误时在最新修订中说明，并通过 Git 指定原版本供复核。纯排版、错别字修复可简记，不得把实质设定变化伪装成文字修正。
3. **同步文件也有自己的时间**：一次设定变更涉及人物主档、世界观、卷纲、章纲、任务卡等多个权威文件时，各自更新本文件最后修订时间和修订记录，并注明变更源头或关联文件；派生摘要应注明所依据的权威版本，不能因为派生文件同步得较晚就反过来取得更高权威。文内历史记录一律归并成最新一次，避免平行维护互相矛盾的版本表；审稿事件账本和叙事时间线仍完整保留。
4. **冲突裁决先核权威，再比时间**：依次确认作者最新明确决定与授权、项目唯一权威设定源、已确认规划、已定稿正文的已发生事实及未确认草稿/建议。**在同一设定项的同级有效版本之间，采用修订时间更晚且已确认的版本，旧版本仅供追溯，不继续作为当前约束。**不同层级或正文与后改设定冲突时，不机械“时间晚者全胜”：先核作者是否明确授权推翻原有已发生事实；没有则登记冲突并请作者裁决，不能静默重写。若新决定已明确批准追溯修订，应同步修复受影响的正文、规划及状态账本并逐项复核。
5. **时间缺失不准猜**：历史文件没有修订时间时标为“历史版本，修订时间待核实”，可利用 Git 历史辅助追溯，但不虚构日期，也不因为无时间就自动判旧设定作废；同秒记录、状态不明、双方来源冲突或证据无法核实时，先列出两边文件、原文、现有时间与确认状态供作者裁决。执行修订后在交付报告列明修改文件、记录时间、采用的新设定、已同步与未同步范围。


**分卷剧情合计的专门例外**：按本 Skill 第2节生成的卷内 `本卷合计.md` 仅是由已有剧情简写/已发生事实提炼的**供读者阅读的派生剧情文本**，不承载新设定、不作为四阶段审核材料或版本裁决依据。为保证文件内**只有剧情**，此文件**不得写入最后修订时间、修订记录、作者说明、审查状态或其他管理信息**；以 Git 历史追溯其修改。原始章节简写、章纲及其他正式设定文件仍须完整执行本节元数据规定。

**本规则用于版本追溯和连续性裁决，不改变既有作者授权边界、唯一权威源（SSOT）、已发生事实保护和四阶段审查权限。**

## 2. 四阶段写作顺序与审核通过准入门禁（强制）

**唯一写作顺序：① 全书大纲 → ② 分卷章纲（内部严格卷纲先通过→才能写章纲）→ ③ 章节简写 → ④ 正式正文。** 这是四个写作产物阶段，不把卷纲和章纲拆成第五阶段；但“同属阶段二”绝非允许未审卷纲先写章纲。新章节、续写新章节和独立插章均适用；插章不占原编号章编号。规划与任务卡的实际目录以当前项目权威配置为准。

**新增写作准入一票阻断（每次新建、续写、扩写、重写必执行）**：严格按 [stage-entry-gate.md](references/guides/stage-entry-gate.md) 在写前核对直接上游当前有效版本、正式审核报告和结论：**写章纲→所属卷纲必须审核通过；写章节简写→对应章纲必须审核通过；写章节正文→对应简写必须审核通过。** 任何缺失、未审、待核实、待复核、不通过、仅有作者历史“已审”确认或上游改稿后旧版审核失效，**直接禁止生成目标新稿（包括待审草稿、临时候选文件）**，不得以“带缺项继续”绕过。整卷/多篇逐篇验证，只有已通过的篇目准写；如果任务含多阶段，必须上游写完→审核通过并留正式证据→才开始下一层，不能先把所有层都写出来再补审。既有稿件的审核、事实核对、授权纠错与必要副本同步仍可按原协议执行，不能借维护之名创作新稿。

1. **全书大纲（阶段一）**：确定全书核心命题、主线冲突、重要人物发展方向、整体阶段/分卷走向和结局方向；以项目权威全书总纲或主线文件为依据。无需预先写出全书所有章节的细纲。
2. **分卷章纲（阶段二）**：**设计时的反刻意检查**：新事件先做下文“主线净收益与反刻意证明”四问，避免先造道德考验再给它添加象征性代价；**仅在该卷卷纲审核通过后才能创作其章纲**；依据全书大纲，明确当前目标卷的主题、目标、主要因果转折和阶段结果，并落实本次目标章节的标题/定位、核心事件、人物选择、承接与伏笔。**每卷须先设计卷首强钩子，落实到卷首第一章并在前3章内形成行动与后果**（详见下方强制条款）。若项目将卷纲和章纲分文件维护，两层材料都须具有与目标范围对应的实质内容；不要求提前完成其他卷的逐章规划。
3. **章节简写（阶段三）**：**仅在当前有效的该篇章纲正式审核通过后才能写该篇简写**；依据目标章的章纲，形成该章/插章完整、连贯的剧情简写，包含时地、在场人物、事件因果、角色选择及代价、关键转折和与前后章的衔接；按项目字数配置及 [剧情审查](references/guides/outline-review.md) 校验。仅有章名、任务卡标题、空模板或生成索引不算简写完成。
4. **正式正文（阶段四）**：**仅在当前有效的该篇章节简写正式审核通过后才能写该篇正文**；依据已核验的前三阶段材料、人物/世界观及已发生事实写作正文，并执行本 Skill 的文学审查和项目工程验收；简写完成且通过剧情审查、其他前置条件齐全时，可自动进入正文，无须逐章等待作者额外批准。

### 分卷剧情合计（章节简写的强制同步阅读副本）

- **文件位置与覆盖**：在项目配置所定位的每一卷“章节简写”文件夹内，固定维护 `本卷合计.md`。已有卷在首次执行时补建；以后该卷新增、修订、删除、拆分或重排编号章/不编号插章简写时，**同一次交付中同步更新**本卷合计，保证内容覆盖该卷当前可确认的完整故事走向。新建卷文件夹并有可用剧情内容时同时创建。只更新受影响卷，不得遗留与当前简写矛盾的旧合计。
- **读者阅读标准（最重要）**：只写**小说剧情本身**：人物面对什么事件、为何采取什么行动、冲突如何升级、付出什么代价、人物关系怎样改变、故事在何处结束并通向哪里；按真实时间与故事因果串联主线及有剧情意义的不编号插章，保留悬念和未知事实，避免堆章名或流水账。允许卷标题和简洁的剧情段落/分幕标题。文字须自然、连贯，没看过作者资料的人也能看懂全卷发生的事情。
- **绝对禁止写入的非剧情**：修订事件或记录、最后修订时间、审核和评分、完成/待审状态、作者/编辑讨论、创作建议、资料依据、文件路径、来源列表、质检结论、章节索引、统计、任务清单、开发流程与任何类似辅助性说明；不把待确认推断写成事实，不提前揭示人物尚不知道的真相，也不自行补造冲突解决结果。该派生阅读文本的版本变化只由 Git 追溯。
- **依据与缺口处理**：优先逐篇阅读本卷所有现行章节简写及独立插章，按当前权威版本整合。若历史卷缺少独立简写，可核对已存在的权威故事摘要或已定稿正文提炼**真实剧情**，但不得凭标题或待办清单臆造情节，也不得把规划当成已发生正文；若不足以覆盖完整剧情，在**交付反馈中**如实说明实际覆盖与缺口，不能在剧情合计中插入管理性占位段落。跨卷连续性以真实正文和项目设定为准。
- **边界**：本卷合计不是第五阶段、不是单章简写替代品，不进行单独剧情评分或阶段放行，不反向改写章纲、单章简写、正文或审核状态；只作同步生成/刷新与剧情核对。无须在合计文件内按第1.1节附加管理元数据。

### 纲要、章节简写、正式正文共同遵守的反刻意与保全叙事原则（强制）

**核心要求：保留真正推动主线的事件，删除刻意安排的人品考验。不为了消除刻意情节而制造新冲突，也不把已经写好的章节简单压缩成剧情摘要。** 本要求适用于全书大纲、卷纲、章纲、章节简写、正文的**新写、续写、改写、审查后授权修订**；应与下方“主线净收益与反刻意证明”共同执行，不新增评分维度。

- **纲要设计**：保留造成主线局势变化、关键因果转折、人物关系/认知变化或有效伏笔回报的事件；识别仅为证明人物正直、善良、专业、守原则而刻意安排的选择、处罚或程序争执，优先删除或将必要信息自然并入已有事件。不得为填补删除后的篇幅、制造“代价”或显得逻辑完整而另造冲突。日常相处、休整、幽默和必要慢戏若有真实的人物或节奏价值，不因不直接推动宏观主线就被机械删除。
- **章节简写**：忠实承接已确认章纲的有效事件链，保留本章行动过程、起因、结果、人物的真实动机和与前后章的承接；删除无独立叙事价值的“人品考验”，不以另一个冲突替换，也不把有效场景裁成只有结论的流水账。若上游仍有刻意设计，依权限先反馈并修订上游，不可擅自偏离已审核通过的章纲。
- **正式正文**：对于已经写好的章节，采取**场景级、段落级最小正收益修订**：移除或自然融入刻意的人品考验，同时保住既有可读的场景推进、人物互动、动作与感官细节、情绪节奏、信息揭示和文学表达。**禁止把原章节大面积删薄、替换成章纲式梗概或剧情摘要；禁止以“去刻意”为由重写出新的人工冲突。** 删除可能影响已发生事实、章节长度、伏笔或后续依赖时，先核验上下游，再按作者授权处理。
- **改后验收**：逐项确认主线因果不缺失、人物动机自然、已发生事实与前后章一致、没有新增补偿性冲突、既有正文仍是完整叙事而非摘要；不满足任一项不得宣称“反刻意修订完成”。

### 卷纲、章纲设计前置的“主线净收益与反刻意证明”检查（强制）

**在设计卷纲、逐章章纲时就检查，而不是先写出刻意支线，等到正文再删。** 每个拟新增的重要事件，先核实它的自然起因、当事人真实目标、与本卷冲突的因果关系，以及会让主线局势、人物关系、角色认知／行动、长期伏笔或读者必要的情绪体验发生什么**具体变化**。禁止为了替主角证明正直、善良、专业、不冷血、事事正确，或为了机械补齐“逻辑合理、必须有代价”，专门增加签字拒绝、道德选择、程序争执、无关伤员、象征性惩罚等考验。**先有真实冲突和人物私心，再有选择；不得先定品格结论再倒造事件。** 这些只是风险示例，并非一律禁用的情节题材。

**四问检查**：（1）若删去或并入既有场景，是否改变后续事件的可达性、人物关系、认知与有用的情绪积累？（2）所谓代价是否在后续真实持续发生，而不是只在章纲写“失奖金/失权限/受处分”？（3）是否重复前章已经证明的立场、救治选择或证据争议，只是更换纸张、机构或人物？（4）该场景的真实动机是否来自人物眼前需要，而非作者代读者追问“他为什么没有犯道德错误”？**四问不是机械的四项评分或“一情节必须推动主线”的硬指标**：必要的生活、幽默、休整、相处、情绪停顿和人物局限，即便不直接推进宏观主线，仍可凭真实的关系/节奏/体验价值保留；不能只用删后“事件结果不变”就粗暴删除所有慢戏。

**修订优先顺序**：先删去纯自证/补丁事件；再考虑把必要信息、选择或合理代价并入既有主线现场；若确实形成不可替代的冲突、人物变化和后续后果才保留完整场景。**不准为了通过审查另造“额外代价”、新冲突或事后解释**。与已定正文、作者确认伏笔/人物命运相关的既有事件，不可凭“看起来刻意”擅删；先核实际后续依赖，保留必要因果，重大变化由作者裁决。审核沿用规划16维/简写七维和P级，不新增分项，不改变阶段一致性及权限规则；审核报告须指出卷章、实质收益、删/并方案及上下游影响。

**卷纲／章纲变更后下游影响清单（必须留文件）**：只要实际改动卷纲、逐章章纲或插章规划，必须在该作品项目的写作计划／审稿目录维护可直接执行的**下游章节影响文件**，逐项列出**全书与卷内编号、旧设计→新设计、直接受影响章、关联核验章、实际存在的简写/正文/阅读副本路径、具体删并与保留事项、缺失文件、执行状态及必要验证**。写明已改上游与尚未改简写/正文/TXT的区别；下游只有在真正写入并复验后才能标完成。用户拟亲自同步下游时，仍先出清单，不擅自把仅已调整的规划冒充正文已同步。既成正文事实及作者锁定主线优先，影响清单不自动授权改写正文或跳过四阶段门禁。本规则不硬编码作品、目录或卷数，定位按当前项目配置。

**每卷开篇强钩子（阶段二强制规划项；2026-11-05 18:42:19 +08:00更新）**：

- 每卷开篇必须有**具体、足以改变人物眼前处境的吸引人情节**，使读者产生明确的追读问题。卷首**第一章就应启动事件/冲突/异常/重大机会或迫切抉择**，不以大段设定播报和流水账热身；**第1—3章内**推动人物作出选择、付出代价或形成新的局面，并让卷级核心问题成立。
- 卷纲必须明确写出**钩子事件、落地章位、涉及人物及利害、关键未知、被迫选择、首轮局部兑现、与本卷主线的因果连接**；对应章纲、简写、正文沿四阶段逐层落实。只写“有悬念/大反转/精彩开局”或只有无因果的悬念句，视为未设计。
- 强度来自**人物所珍视之物可能得失、事态真实变化、悬念与后果**，不要求惊天事故、打斗、死人、反转或重复刺激；可使用关系、伦理、情绪、利益、真相、行动等不同类型。不得违背已发生事实、人物能力、世界规则，不得靠误会、降智、凭空设定或空头承诺硬造爆点；钩子要安排合理的早期阶段回报。
- 新卷规划缺少可执行的卷首钩子时，按阶段二缺项提醒/质量审查如实说明，**不得将该卷规划标为已准备好进入简写**。独立审核遵照 [outline-review.md](references/guides/outline-review.md) 既有16维与P级，不另设评分；已有正式正文不能因补钩子而被擅自推翻。具体写法参照 [分卷因果指南](references/guides/deep-plot-volume-guide.md) 和 [钩子技巧](references/guides/hook-techniques.md)。

**进入下一阶段前的写作准入核验（每次新创作必做）：**

- **先校验审核通过，后写任何新稿**：写章纲核该卷现行卷纲的**正式审核通过**；写简写核该篇现行章纲的**正式审核通过**；写正文核该篇现行简写的**正式审核通过**。必须查到审核报告及可核版本证据，按 [stage-entry-gate.md](references/guides/stage-entry-gate.md) 实施。**只存在文件、完成写作、作者确认曾经“审核过”、质量总分达标或旧版本 PASS 均不足以放行。**
- 用户要求直接做阶段二时核对阶段一主线等约束；做阶段三时核对阶段一、二与该篇章纲的正式通过；做阶段四时核对阶段一、二、三与该篇简写的正式通过。先从有效版本和卷章/插章映射获取真实记录，再执行 [相邻上游一致性硬门禁](references/guides/stage-consistency-gate.md) 的相关事实约束。新写作请求不能把只读索引、占位或失效的旧稿当作审核证据。
- **任一直接上游审核未通过、缺少正式报告、范围不覆盖目标篇目或与当前版本不一致，立即 `BLOCKED`**；按卷章分别列“拟写成果物、缺失的上游有效审核、当前记录/缺口、下一步先审核或修复哪份上游”。**禁止创建下游待审草稿，也不能通过作者对本次普通写作请求的“先继续”授权绕开硬门禁。**需变更这条规则，必须由作者另行明确要求修改规则本身。
- 完成上游审核且正式记录“通过”后，重新核对当前版本再进入下游；多卷/多章请求只对已通过的具体目标执行，其余记录阻断。**针对既有正文的审查、复审、授权的局部修订、事实回写和格式同步，不应仅因历史规划缺项而一概停止维护；但这不允许新写或扩写不符合门禁的章节。**

- **初始化/设计**：按 [phase0](references/flows/phase0-initialization.md)、[主题定位](references/flows/phase1-layer1-core.md)、[定制](references/flows/phase1-layer2-customize.md)、[标题](references/flows/phase1-layer3-title.md)、[规划](references/flows/phase2-planning.md) 按需执行；已有项目不重新初始化。
- **全书大纲／分卷章纲／章节简写**：检查主线目标、各方利益、人物选择、代价、阶段钩子、伏笔及世界状态；**前两阶段按剧情16维评分，简写按剧情七维评分**，互不叠加。禁用正文词频、翻译腔、PAM及37项语言AI味评分；简写目标字数仅列工程就绪度。按 [剧情审查](references/guides/outline-review.md)。
- **详写**：按 [写作流程](references/flows/phase3-writing.md) 与 [v8适配](references/flows/webnovel-writer-v8-adapter.md) 按需备料，检查在场人员、小传、角色知情与时间线；对温度、物态、负重、装备性能、距离、耗时、资源消耗等关键客观描写先核现实物理常识及数量级（详见核心协议），不能靠看似专业的数字制造不成立的场景；依据当前项目已确认的文风和人物声口起草；用自然、常见的中文语序和搭配写清动作主体及句间关系，避免需要回读才能理解的拗口表达，保留有作用的倒装、口语和人物声口。**写第一稿就核每个说话人的身份与声口：人物对白默认使用符合身份、情绪和场景的自然口语，先说眼下具体的人、事和要求，允许省略、插话、停顿、口头惯用语和不完整句，不为交代设定强写成完整汇报；尤其避开公文式绕弯、免责腔、冗余否定、程序化决策台词与多人统一口吻（按AI味37项中第32、34、36项裁决）**，不得靠模板化动作、说教、台词里的密集比喻制造深刻。审后依据 [质量核心协议](references/guides/review-core.md) 做**一次综合语义审查**，已确认问题再改；机械扫描只定位候选，若项目工程门禁另有要求可运行一次，不代表语义审稿完成。
- **描写、人物与对白**：描写服务于剧情、人物或情绪，同时保留能体现处境、关系或节奏的慢戏和生活细节。人物通过具体欲望、软肋、底线，以及有来由的内在张力立起来；不为制造戏剧性而强造矛盾。对话推动信息、关系或行动，也允许闲谈承担日常感和节奏。**正文对白要像人物在现场开口说话，不是作者借人物之口归纳流程、条款和结论**；同一场景中的角色须有不同的词汇、句长、反应和省略习惯。专业交接、岗位指令、合同等有必要时可准确正式，但普通交谈不得默认公文化；口语化不等于全员粗口、全员短句或刻意填充语气词。正文起草和审查均按 [核心协议](references/guides/review-core.md) 的“具体描写与对话的人工复核”检查信息堆叠、重复解释、人物出场和对话提示；这是阅读质量线索，不保证降低第三方检测分数。
- **验收**：工程文件存在、项目字数、阶段材料、时间线/事实账本及双格式同步，按 [phase4](references/flows/phase4-validation.md) 与项目配置校验；与文学质量评分严格分开。变更后的受影响范围才复检，不对未改章节重复运行全套。

可用的 `webnovel-init/plan/write/review/query/learn/dashboard/doctor` 是**意图映射**，不是一定真实存在的可调用命令。查询/学习/仪表盘/诊断参阅 [v8适配](references/flows/webnovel-writer-v8-adapter.md) 和 `scripts/novel_workbench.py`；没安装的外部工具、没有派生的子Agent、没有实际运行的检测服务绝不声称已经调用。

## 3. 统一审稿（四阶段分流，正文独立协议）

- **唯一裁决来源（按阶段）**：全书大纲、分卷章纲、章节简写按 [outline-review.md](references/guides/outline-review.md) 的对应量表；**正式正文**按 [review-core.md](references/guides/review-core.md) 的七维权重、37项AI味、P级、优化阈值与轮次。[chapter-review-default.md](references/guides/chapter-review-default.md) 只决定正文操作步骤；四份提示词不是新增评分制度。旧四关与历史模板不作为叠加门禁。
- **相邻环节硬门禁**：初审先核对目标稿与有效直接上游的完整对应关系：卷纲对总纲、章纲对卷纲、简写对章纲、正文对简写；记录原设计、实际落实、差异证据与最强反证。确证关键事件/抉择/结果/代价/顺序/职责偏离，即使分数达到80以上仍直接打回；上游缺失则暂缓通过；复审消除差异后才可改判。只改变通过条件，不增设评分。
- **实读与反证**：先登记真实版本、全文和相关设定的可读范围；剧情问题与正文逐段语言问题同轮审查，并按 [核心协议的物理常识必检条款](references/guides/review-core.md) 核查场景、人体、器材、时空和资源条件，关键数字须核对量级；独立反方可用才真实调用，否则标明单模型反证；脚本、词频、第三方检测只提供候选。相同根因只归一个主问题，不重复扣分。
- **分阶段修订**：前三阶段审核默认只读，只有本次明确授权才按净收益门禁修规划，不套正文五轮阈值。正式正文主动审核未指定只读时按核心协议自动最小改稿、复验与必要派生同步；重大情节待决、证据/权限不足或净收益不明则停止不安全写入并说明。
- **真实交付**：前两阶段给16维表、跨卷/逐章覆盖与具体方案；简写给七维及逐章因果台账。**正式正文**完整报告保留37项全部裁决，最终展示问题项证据、正文七维分项/总分、改前改后、真实工具状态。不得用抽样代替完整目标范围，也不能声称未运行的 TXT/合订本校验通过。报告与停止条件以本阶段协议为准。
- **按需资料**：遇到特定疑点才读 `references/ai-tone/` 中的历史 G1—G4、PAM、TR/TX、统计研究和案例；需要候选定位时运行相应 `scripts/` 工具；这些均不增加必经关卡。

### 章节最终审核总表（正式正文每章复审后必维护）

- 每次完成正式正文单章、多章或整卷的**有证据的最终审查/复审和审核报告**后，须同次维护该作品唯一的「章节最终审核总表」，**一章（含独立插章）一条当前结果**；再次复审更新原行，历史轮次留在正式报告。详细字段、Excel工作簿/CSV镜像、统计与核对规则见 [章节最终审核总表维护规范](references/guides/chapter-final-review-register.md)。
- 优先使用项目已有的审核总表及报告归档目录；没有时在该项目审核目录建立 `章节最终审核总表.xlsx`（本仓采用 `08-审稿/章节最终审核总表.xlsx`），可维护同数据的 CSV 机器可读镜像。总表记录章节定位、正文及报告版本、**初审/最终七维总分、最终七维原始分、分数变化、AI味37项专项结论、问题修复与遗留P级、文学/工程独立结论、正文及适用副本同步状态、日期和报告路径**；按卷统计和最低分章节依真实最终分计算。
- **不新增评分体系**：正文总分沿用 `review-core.md` 唯一七维权重；**AI 味专项只记录“通过/不通过/待复核”等裁决，绝不虚造 AI 味分数、百分比或生成概率**。缺证据留空/待核实，不能按历史旧量表或聊天结论补填；不得把总分高当作AI专项或工程门禁已通过。
- 先完成文学复审、正式报告及当前项目要求的源稿/导出副本核验，再更新总表并验证键唯一、分数/状态一致、统计未计未审章节。**当次明确只读时不写表**；无能力实际写入、校验 XLSX/镜像时必须报告阻塞，不得声称同步完成。总表只做汇总索引，不能替代逐章语义审查与完整报告。

## 4. 写后事实与双格式交付

- **唯一正文源**：先从当前项目配置或已有文件确定正式正文的权威格式与目录，禁止固定套用任何示例作品的正文目录。若项目使用 Markdown 源稿与 TXT 阅读副本，则只修改源稿、由项目对应的导出工具生成阅读副本，不能反写；本 Skill 提供的 `scripts/export_reading_txt.py` 仅在该项目采用其格式/参数时使用。段首缩进、场景空行、编号和字数均按当前项目规范核验；没有导出副本要求的项目，不强制产生 TXT 或合订本。
- **事实回写**：审核通过的已发生事件才更新项目实际维护的人物经历、身体状态、关键道具、关系、时间线、伏笔及动态账本；未发生的候选情节不得入“已发生”账。涉及设定、小传、总纲、卷纲、章纲及相关规划的实际变更，必须同步执行第1.1节的时间标注与逐文件修订记录。每卷完成后进行一次全卷与相邻卷的连续性复核，再推进新卷。不同来源冲突先查确认状态、权威来源与修订时间，再按第1.1节裁决或提交作者决定。
- **工具与人工分开**：`scripts/verify_chapter_consistency.py`、`scan_chapter.py`、`scan_ai_tone.py` 为工程检查/候选扫描，结果不等于完整质量审查；必要时按项目技术规范阻断交付，但不反向制造文学质量P1。没有正收益的“去AI味”改稿可以不改。
- **通用经验仍在**：`references/guides/` 是写作方法库，`references/ai-tone/` 是文本风险与真实案例库，`references/flows/` 是阶段工具指南，`scripts/` 保留既有写作辅助/统计/检测能力。**只按当前任务读取需要的文档，禁止把“历史必读”叠加成新关卡。**

## 5. 质量规范优先级

**当前用户明确要求 > 当前项目权威配置/已定事实 > 本文件及 `review-core.md` > 单项参考文档、历史模板、过去的对齐表。**过去写在旧参考里的“每次全文强制读若干篇/逐项全跑/独立重复计分”，一律由本精简入口取代。写作工程的原有独立脚本仍可用，但必须报告实际执行与未执行状态。
