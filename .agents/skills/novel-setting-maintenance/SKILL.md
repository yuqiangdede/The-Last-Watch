# novel-setting-maintenance｜小说设定一致性维护

## 适用与入口

用户提出“清理设定”“同步旧设定”“检查所有卷纲章纲冲突”“整理人物小传与世界观”“维护设定一致性”时使用。本 Skill **只接受人工触发**；不得自行创建 GitHub Actions 定时器、cron、自动化提醒或后台巡检。

本 Skill 是**设定维护**，不是文学审稿、创作续写或删稿。保留 `chinese-novelist` 原有四阶段写作、修改时间与授权协议；不添加独立文学分数。阅读当前项目 `AGENTS.md`、`novel.project.json`、现有权威来源和 [范围与权威](references/scope-and-authority.md)，严禁将本作品专属事实移植到通用 Skill。

## 严格文件边界

**允许扫描、按证据安全修订：**
- `01-世界观/`：全部世界规则、势力、经济、地理、科技与社会背景。
- `02-人物/`：全部人物主档、小传、关系及人物总表。
- `03-剧情/全书主线.md`、`03-剧情/卷纲/卷大纲.md`、同目录所有独立卷级细纲及 `03-剧情/章大纲/第NN卷.md` 的**每一个存在的章节与插章**。对《崖边戍卒》必须覆盖第01至第20卷，缺卷视为未完成而不是跳过。
- `04-文风/` 中承载具体设定的项目专属规则、`05-写作计划/` 内任务卡和规划文档、`07-创作记忆/` 动态状态、根目录的有效项目配置和设定性索引，及其他真正影响小说事实的有效文件。
- `05-写作计划/章节规划总表.md` 只能调用原有 `build_chapter_index.py` 生成，**不手改**。`07-创作记忆/作者人工复核进度.md` 不自动修改。

**强制只读参考，绝对不改：**
`06-正文/`、`06-正文-TXT/` 及其阅读/合订本副本、`05-写作计划/章节简写/` 下全部文件。已有正文属于已发生事实；既有简写为规划证据但本任务无修订权限。不得为了“冲突归零”反向改正文或简写。历史 `09-归档/` 只用于追溯，不当现行设定，也默认不改。

## 手动执行流程（全量模式为默认）

1. **定位与覆盖**：记录仓库分支、当前版本、全部设定文件清单；读取所有权威文件。对项目当前20卷依次验证卷纲导航、卷级因果细纲、逐章章纲，逐章核对总纲和人物/世界观；检索受影响任务卡、动态记忆与项目规则。不能抽样代替20卷全量检查。章号区分全书内部号、卷内号、不编号插章；必须确认现行目录及可读状态。
2. **机械候选与证据索引**：在本地完整工作树中运行 [只读脚本](scripts/audit_setting_structure.py)，例如：
   `python .agents/skills/novel-setting-maintenance/scripts/audit_setting_structure.py --project-dir . --expected-volumes 20 --term 杜川 --term 联域 --output 08-审稿/设定一致性维护/巡检证据.json --check`
   该脚本只检查结构、目录、链接、版本标签及给定关键词证据；**不能替代逐文档语义审阅**。如工具不支持运行，必须记录“未运行”，依实际读取材料审阅，不得虚称全覆盖。
3. **语义审查**：按 [检测矩阵](references/semantic-audit.md) 对每个卷、每个章、每份人物及世界设定审查八类风险；每条事实建立“对象—属性—生效时间—卷章—事件—状态—原文—来源”的证据链。核实叙事时间线和观察者知情范围，排除人物成长、谣言、旧记录引用、未确认提案与真实矛盾之间的混淆。
4. **权威裁决**：按 [冲突裁决协议](references/conflict-resolution.md) 执行。只有真实证据足以唯一确定旧版本失效、不会改变已发生正文事实及锁定情节时，才允许 **A类安全自动修复**；B类证据不全继续调查，C类重大命运/核心世界规则/正文冲突停止并交作者。时间晚、关键词匹配或多数文档一致，**均不能单独作为裁决证据**。
5. **最小正收益修复**：只修改确证过期的当前有效表述，不扩写故事、不凭空补设定、不删独有有效信息；相关人物小传、世界观、卷纲、章纲、任务卡、动态账本同步。每个实际写入的设定文件遵循 `chinese-novelist/SKILL.md` §1.1：真实写入时刻及项目时区、逐文件原设定→新设定、依据、确认状态，并把现行文档的历史修订条目归并为**最新一次**。同一文件仅保留**最新一条修订元数据**（最后修订时间和最新一次变更摘要）；旧版修订条目从现行文件清理，完整变更历史依 Git 追溯。不得删除叙事中的真实事件日期、角色时间线或其他有效设定事实。
6. **派生与复验**：章纲改动后运行 `python .agents/skills/chinese-novelist/scripts/build_chapter_index.py --project-dir .` 及 `--check`，仅生成对应索引。复核所有改动后的文档、前后卷、人物状态、引用路径；确认只读目录及人工进度文件没有变化。修复后再次扫描同一证据范围，不因脚本无报错就宣称语义一致。
7. **报告与提交**：按 [报告模板](references/report-template.md) 生成 `08-审稿/设定一致性维护/` 下的冲突台账、分卷覆盖表、解决清单和待作者裁决清单。无可核证的冲突时应报告“本次未证实冲突”，不能假造修改。按照项目 `AGENTS.md` 的 Git 授权对本任务相关变更直接在目标分支提交/推送，**不建 PR**；仅确实成功后才报告提交 SHA。

## 停止条件

- 未能读取完整范围：明确列出缺失卷、缺失文件与未审章节，不能写“全量通过”。
- 来源、状态或修订时间无法裁决：登记两侧原文与位置，维持原状。
- 后设定要求修改正文事实、章节简写、人物重大命运或作者锁定结局：不可越权。
- 同一安全修复第二次执行没有新证据时**必须幂等**，不得重新替换、重打时间戳或生成无意义新提交。
- 没有真实 Agent 语义审读时只能称“结构/候选巡检”，不能称“完成设定一致性全面检查”。

- “仅检查全书20卷卷纲、逐章章纲的跨卷连续性，不做任何修改。”

只读请求不得生成或修改内容文件；显式“只检查”优先于自动修复默认权限。


## 修订元数据唯一性门禁

- 对**允许修改的非正文、非简写文档**：每份现行文档仅保留一处 `最后修订时间` 和一条最新的 `修订记录`；每次有效改动覆盖旧摘要，旧条目由 Git commit 历史保存。
- 裁决“哪个设定更新”以**来源权威、作者确认、生效范围、源文件 Git 记录、时间顺序**共同判断，不得把修订日志清理等同于设定裁决，也不得用刚执行的日志整编时间反向夺取主档权威。
- 文内“2145年”等**故事事件时间**、政策生效日期、用于解释因果的原始文件日期均不属于应删历史修改时间。审核报告与证据台账如有必须保留的多次审核事件，也不得为满足展示简洁而破坏审计链；现行设定文档只展示最新摘要。
- 发现旧稿与现行稿冲突时先确认旧稿是否仍是有效入口：已停用稿可删除（Git 留痕），有效稿只清除确认失效的断言，不能因日期较晚擅删独有剧情或作者未裁决内容。

## 与创作进度台账的联动

安全修订涉及卷纲、现行章纲、章数、插章位置或新版章纲切换后，应执行 [novel-progress-ledger](../novel-progress-ledger/SKILL.md) 的进度表重新生成与只读校验；台账不是小说设定权威，不可反向覆盖源章纲。仅更新阶段进度和有据的审核记录，不因设定冲突清理而自动修改正文、简写、正文终审表或作者人工复核进度。本 Skill 仍然只接受人工触发。
