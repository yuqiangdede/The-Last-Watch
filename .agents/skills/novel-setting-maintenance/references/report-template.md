# 小说设定一致性维护｜报告模板

> 本模板为维护任务的证据与交付结构，不是质量评分体系。

## 1. 基本信息
- 小说名称 / Git 分支 / 扫描开始时的版本 / 本轮执行日期：
- 扫描模式：全量 / 指定卷及关联范围；是否只读：
- 实际使用的工具与指令：脚本成功 / 未运行、Agent实读范围、仓库可写状态：
- 正文、TXT、简写和作者人工复核进度：**只读保护检查结果**：

## 2. 全量覆盖矩阵
- 世界观：应查文件 / 实读文件 / 未读：
- 人物小传：应查 / 实读 / 未读：
- 全书主线、卷纲导航：应查 / 实读 / 未读：
- 独立卷级因果文件：文件名及逐份读取状态：
- 逐卷章纲：**第01至20卷分别列出**，每卷给出实际章节行数、插章数、已确认/拟定情况、语义审核状态和无法审阅的章节；
- 其他项目规则、任务卡和动态账本：应查 / 实读 / 未读：
- 若不全量：说明筛选依据，严禁写“全书无冲突”。

## 3. 冲突台账（逐项）
| ID | 设定项 | 来源A（路径、行、原文、修订时间和状态） | 来源B（同上） | 反证 | 等级 | 裁决 | 修改及回查 |
|---|---|---|---|---|---|---|---|
| SET-001 | 示例 | 待提供证据 | 待提供证据 | 可能只是状态变化 | 待核 | 不做决定 | 原样保留 |

历史记录需追溯；单凭关键词命中不能作为实质冲突。相同根因合并记录，不重复计数。

## 4. 修改清单
每份文件：变更前后原文、作者确认依据、实际写入时间、修订记录位置、受影响卷章、验证结果。若无确证A类问题写“未修改”，不要虚报清理成果。

## 5. 未解决与阻塞
B/C问题、分歧双方、涉及正文不可写的原因、推荐作者确认的一条或多条具体选项及对后续卷章的影响。

## 6. 复验与提交
机械检查、生成索引 `--check`、受影响语义复查、保护目录无改动、幂等复跑（若实际执行）、Git diff 与提交SHA。未执行项必须列出原因。

结论区分 **结构检测结论** 与 **人工/Agent语义一致性结论**，不得互相替代。
