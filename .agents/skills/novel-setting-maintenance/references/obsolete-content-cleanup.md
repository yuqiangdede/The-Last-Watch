# 过时内容清理流程

作者要求“清理过时内容”时，从当前工作树和实际有效规则出发；若未指定范围，盘点整个项目，包括根目录、设定、规划、辅助视图、Skill、脚本、审稿记录及临时资料。默认不仅处理文件，还要逐文件语义检查允许修改的非正文内容中的过时角色状态与其他失效表述；涉及全书设定一致性的请求还须执行主 Skill 的相应检查和覆盖要求。

1. **盘点与定位**：记录分支、Git 状态及已有未提交变更，区分受跟踪、未跟踪和忽略文件；查看目录、配置、项目约束、有效入口、引用及生成/读取路径。搜索结果、文件日期、未被引用或自动扫描命中仅是候选，不是可删除的证明。按实际需要核查 Git 历史和内容，明确当前权威版本、用途及是否仍有独有信息。
2. **角色状态逐项清理**：遍历范围内允许修改的现行非正文文档，包含人物主档、关系、世界观、剧情、卷纲章纲、任务卡、动态记忆及其他引用人物状态的有效资料，逐人定位身份、所属、位置、伤病、生死、关系、能力、装备及经历等表述。对每一候选核对人物权威主档、动态账本、作者明确裁决及相关已发生正文，记录来源、适用故事时间、确认状态和受影响位置；搜索只用于定位，不能代替阅读语境。以当前权威状态更新当前状态栏及无时间限定的现行描述，删除或改写已确认失效的旧版本、重复快照和误作现状的旧断言，并同步所有已核实的有效落点。不能将计划、预测、传闻或派生摘要当成已经发生的最新事实。
3. **保留必要的时间层次**：卷纲、章纲、任务卡与人物经历可能描述特定历史或未来阶段，须保留该阶段真实状态、事件因果、人物成长和伏笔；不要把最终状态机械覆盖到更早章节，也不能把未来规划写成现状。清理的是被新证据取代或误导为现行的旧设定，不是抹除故事内历史。无法确认生效时间或权威、涉及重大命运或与正文冲突时先查证，仍无法裁决则保留并报告。正文及其 TXT、简写、历史档案、审核证据和作者人工复核表继续遵守主 Skill 保护边界。
4. **分类裁决**：逐项判断是现行内容、已确认过时的断言或文件、可重建的临时产物、必要历史证据，还是用途/权威不明。对已确认过时的有效入口，优先最小修正或标明历史状态；仅当确认不再有效、无独有价值且不存在未处理依赖时删除或合并。重复文件也须先比较内容及用途。证据不足、可能有独有价值或重大设定争议的项目保留并列待核/待作者裁决，不能仅因 Git 可恢复而删除。
5. **保护边界**：遵循项目与主 Skill 的正文、TXT、章节简写、作者人工复核表及历史档案保护要求；已有审稿报告、审核事件、作者确认和叙事时间线不得因过时或重写而抹除。清理请求本身不授权删改正文、简写、重大剧情、人物命运或世界规则。用户明确指定的删除范围仍须服从其他适用约束。保护已有无关未提交变更。
6. **修正并同步**：依作者最新明确决定及权威来源处理冲突，保留确有作用的原文；调整文件位置时遵循根目录约束，并同步现行文档、配置、脚本、初始化及生成路径，防止旧文件被重新生成。不要批量改写历史证据中的原始路径；必要时增加现行定位说明。阶段成果物状态变化时按 `novel-progress-ledger` 直接更新对应逐篇和卷级台账，保留真实历史审核事件，禁止编造完成或通过。没有完成逐项核验时明确标注未完成，不以总提示代替实际台账更新。
7. **复核与交付**：检查受影响入口、引用、生成路径和适用脚本，做与改动相称的验证；分别报告实际检查范围、角色及状态检查覆盖、已删/合并/修正项目（含角色状态及依据）、保留或待裁决项、未检查范围、验证结果及限制。严格区分候选扫描和语义审阅，不因部分检查完成宣称全项目已清理完毕。按项目 Git 规则只提交本任务文件、核对远端并推送；无变更不造提交，失败如实说明。用户明确要求只读、不提交或不推送时从其要求。
