# 过时内容清理流程

作者要求“清理过时内容”时，从当前工作树和实际有效规则出发；若未指定范围，盘点整个项目，包括根目录、设定、规划、辅助视图、Skill、脚本、审稿记录及临时资料。只检查不等于逐篇语义审阅；涉及全书设定一致性的请求还须执行主 Skill 的相应检查和覆盖要求。

1. **盘点与定位**：记录分支、Git 状态及已有未提交变更，区分受跟踪、未跟踪和忽略文件；查看目录、配置、项目约束、有效入口、引用及生成/读取路径。搜索结果、文件日期、未被引用或自动扫描命中仅是候选，不是可删除的证明。按实际需要核查 Git 历史和内容，明确当前权威版本、用途及是否仍有独有信息。
2. **分类裁决**：逐项判断是现行内容、已确认过时的断言或文件、可重建的临时产物、必要历史证据，还是用途/权威不明。对已确认过时的有效入口，优先最小修正或标明历史状态；仅当确认不再有效、无独有价值且不存在未处理依赖时删除或合并。重复文件也须先比较内容及用途。证据不足、可能有独有价值或重大设定争议的项目保留并列待核/待作者裁决，不能仅因 Git 可恢复而删除。
3. **保护边界**：遵循项目与主 Skill 的正文、TXT、章节简写、作者人工复核表及历史档案保护要求；已有审稿报告、审核事件、作者确认和叙事时间线不得因过时或重写而抹除。清理请求本身不授权删改正文、简写、重大剧情、人物命运或世界规则。用户明确指定的删除范围仍须服从其他适用约束。保护已有无关未提交变更。
4. **修正并同步**：依作者最新明确决定及权威来源处理冲突，保留确有作用的原文；调整文件位置时遵循根目录约束，并同步现行文档、配置、脚本、初始化及生成路径，防止旧文件被重新生成。不要批量改写历史证据中的原始路径；必要时增加现行定位说明。阶段成果物状态变化时按 `novel-progress-ledger` 直接更新对应逐篇和卷级台账，保留真实历史审核事件，禁止编造完成或通过。没有完成逐项核验时明确标注未完成，不以总提示代替实际台账更新。
5. **复核与交付**：检查受影响入口、引用、生成路径和适用脚本，做与改动相称的验证；分别报告实际检查范围、已删/合并/修正项目、保留或待裁决项、未检查范围、验证结果及限制。严格区分候选扫描和语义审阅，不因部分检查完成宣称全项目已清理完毕。按项目 Git 规则只提交本任务文件、核对远端并推送；无变更不造提交，失败如实说明。用户明确要求只读、不提交或不推送时从其要求。
