# 冲突裁决与安全自动修复协议

## 裁决顺序

1. 收集冲突两侧完整上下文、具体文件与行、原文、适用叙事时间及确认状态；若缺文档记待核。
2. 排除同一人物前后阶段变化、角色的不可靠情报、作者刻意的悬念、多版本草稿、修订记录对旧设定的历史引用。
3. 查作者最近**明确确认**的相关决定及其适用范围；查领域权威主档和已定稿正文中的已经发生事实。
4. 同一设定项、同层级且均确认时，用**可核实的较晚修订时间**裁决；派生摘要的同步时间不能提升权威。若权威来源或时间缺失、互相矛盾，标记待作者裁决。
5. 后续作者要求推翻已发生正文或锁定人物命运，只有明确批准了追溯修订及同步范围才能讨论；本 Skill 仍**不修改正文及章节简写**，因此只登记阻塞，不代替专门正文修订流程。

## 风险分级

| 等级 | 必要条件 | 行为 |
|---|---|---|
| A 安全修复 | 有唯一且已确认权威来源、过期描述可精准定位、不会破坏其他有效信息或正文事实、修订净收益明确 | 在允许写入的当前设定/规划文件最小修订并复查 |
| B 待复核 | 意图明确但来源、时间、上下文或叙事阶段有缺口 | 先补查上下游；不能裁决时保留并报告 |
| C 作者裁决 | 核心人物命运、不可逆事件、结局、世界规则重大变化、同级权威相争、正文矛盾 | 禁止改写争议项，提供方案和影响面 |

## 可执行修订约束

- 不使用全仓无差别 `str.replace` 清理自然语言设定；先定位到当前有效段落，逐位置证据核查。历史修订记录按作者新规则仅保留最新一条，其余通过 Git 追溯；不要因此删除有效原文引述、人物在过去“曾经误认为”的叙事及已发生故事时间。
- 不删除未涉及矛盾的有效设定、人物经历与独有情节；不能因为信息只在某份旧文档出现就认定其无效。
- 修改时间采用**实际落盘时刻**及项目指定时区，逐文件**覆盖为单条最新修订记录**，注明“原设定→新设定、理由、依据、确认状态”；旧记录通过 Git 追溯。无实际内容变化，不更新时间与历史条目。
- 世界观、人物主档优先更新，再修有效总纲、卷纲、独立卷级细纲、逐章章纲、任务卡、动态记忆。派生索引按原生成程序重建。
- 在完成修改前，冻结受影响的正文、TXT、章节简写与作者人工复核进度原值；修改后检查 Git diff，不允许这些文件出现改动。
- 复审相同冲突的全部现行有效落点及邻卷、跨卷人物状态。出现新冲突立即回滚有害改动并记待裁决。
- 幂等：同样输入第二次运行没有确认的新冲突时，不作重复“修订记录”、不生成无意义提交。

## 反面示例

- “最近修改的摘要一定权威”——错误；需看主档、确认状态与派生关系。
- “章纲写了将来入队，人物小传写现在未入队，所以矛盾”——通常错误；先核实时间。
- “旧修改记录含过时路径就反向修改叙事事实”——错误；旧日志可从现行文档精简到最新一条，历史证据从 Git 追溯。
- “正文与新设定冲突就直接改正文”——禁止；记录作者确认所需决策。
